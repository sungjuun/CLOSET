# 코디 모듈 계약

O01 구현: `draft.ts`(슬롯/검증/순수 변경), `selection.ts`(읽기 서비스 경계), `queries.ts`(회원별 조회/취소), `Board`/`Picker`/`EditorScreen`을 사용한다. 기본 아우터·상의·하의·신발 2×2와 원피스·가방·액세서리 추가 슬롯을 제공한다. 슬롯당 의류 하나, position=0이며 같은 옷 중복은 거부한다. 여러 레이어/position 재정렬은 후속이다.

PC는 왼쪽 35% 선택 패널과 오른쪽 보드, 모바일은 보드에서 여는 전체 선택 화면이다. 의류 검색/분류/브랜드/색상/계절/즐겨찾기와 20개 페이지를 제공한다. 후보는 본인 active/미삭제/해당 종류만 조회한다. 선택 직전 새로 읽고 소유권/상태/분류를 검사한다. 선택된 ID는 별도 배치 조회로 30초/포커스/수동 재검사하며 상태가 바뀌면 슬롯 경고를 표시한다. 구성 검사는 최소 1개, 코디 이름·메타데이터와 현재 의류 상태를 다시 검사한다.

초안에는 이름/계절/상황/태그/메모/즐겨찾기/슬롯 ID만 메모리로 유지한다. signed URL은 초안에 넣지 않고 기존 private 사진 Query로 표시한다. 회원 교체 때 초안/조회가 폐기된다. Expo Router usePreventRemove와 공통 메뉴 GuardedLink를 함께 사용해 미저장 이동을 확인한다. 초안 비우기/이탈은 사용자 확인 후에만 진행한다. 새로고침/닫기는 SDK beforeunload에 의존하며 실제 대화상자 검증은 남아 있다. 앱 강제 종료/세션 경계/개발 HMR은 초안 보존을 보장하지 않는다.

O02 구현: `repository.ts`의 저장/복제/삭제는 `save_outfit`/`copy_outfit`/`delete_outfit` 단일 RPC 트랜잭션이다. 서버는 auth.uid()로 소유자를 결정하고 본인 active/미삭제/슬롯 분류/최소 1개/중복/position=0을 검사하며 의류 SHARE 잠금을 커밋까지 유지한다. DB 직접 쓰기는 계속 차단한다. 읽은 updated_at 원문으로 수정·복제·삭제 충돌을 검사한다. 새 코디/복제 ID를 재시도에 유지하고 정확히 같은 원하는 상태는 기존 행을 반환한다. 삭제는 soft delete로 의류와 과거 착용 스냅샷을 보존한다. 코디 복원/영구 삭제는 제공하지 않는다.

`EditorScreen`은 새 코디/기존 코디 편집을 공유한다. `/outfits/[outfitId]`는 회원별 snapshot을 한 번 폼에 넣으며 백그라운드 재조회 오류가 초안을 지우지 않는다. 충돌·실패 시 입력을 유지하고 사용자 확인 후 최신 내용으로 교체한다. 지원하지 않는 레이어 구성은 조용히 잘라 저장하지 않고 편집을 거부한다. 쓰기는 작업 시작 토큰을 고정하고 15초 취소를 전달하며 해제/계정 경계 후 결과를 폐기한다. 최신 근거는 `docs/PHASE_08_VALIDATION.md`다.

O03: `catalog.ts`/`CatalogScreen.tsx`는 `search_outfits` RPC로 이름·메모·태그·현재 구성 의류 브랜드를 대소문자 무시 리터럴 부분 검색한다. 브랜드·태그는 정확 일치, 계절·즐겨찾기를 포함한 조건은 AND다. 보관/판매/기부된 옷은 브랜드 검색에 포함하지만 휴지통 의류와 삭제 코디는 제외한다. `outfit_filter_options`는 본인의 전체 미삭제 코디 기준 브랜드/태그를 중복 없이 반환한다. 선택지는 다른 필터/현재 페이지와 독립적이다.

최근 추가/수정/오래된 추가/이름순 정렬과 12개 서버 페이지, 전체/필터 개수, 중첩 구성 전체와 비공개 사진을 제공한다. EXISTS로 여러 의류가 검색에 맞아도 코디는 한 번만 집계한다. 마지막 페이지 삭제 시 재집계하며 조건 변경/초기화는 페이지를 0으로 돌린다. Query key는 회원/페이지/모든 정규화 조건을 포함한다. 코디 쓰기 뒤 코디/옷장 캐시를, 의류 변경 뒤 옷장/코디 캐시를 무효화한다. 최신 검증은 `docs/PHASE_09_VALIDATION.md`다. O02 쓰기·O03 새 필터 UI의 브라우저 검증, 실기기 검증은 남아 있다.
