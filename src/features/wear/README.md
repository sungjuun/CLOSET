# 착용 기록 모듈 계약

H01: `record_wear_event` RPC는 착용 이벤트와 당시 의류 ID 목록을 한 트랜잭션으로 저장한다. 코디 기반은 선택 시 읽은 outfit ID/updated_at 원문을 전달한다. 개별 의류 기반은 UUID 배열을 전달한다. 두 입력 모드는 함께 지정할 수 없다. 새 기록에는 본인 active·미삭제 의류 1–50개만 허용하며 중복은 거부한다.

코디는 기존 쓰기와 같은 advisory 잠금, 의류는 UUID 순서 SHARE 잠금을 커밋까지 유지한다. 코디 수정이 먼저 커밋되면 오래된 버전 요청은 거부한다. 기록이 먼저 잠기면 코디 변경은 기록 커밋 뒤 진행되며 과거 목록은 그대로다. 같은 날짜/같은 코디도 새 기록 ID면 별도 이벤트다. 같은 ID/정확한 원래 요청의 재시도는 무변경 성공이며 날짜·메모·모드·원본 버전·수동 구성 변경은 충돌이다.

`source_outfit_id`/`source_outfit_updated_at`은 원래 요청의 출처를 보존한다. 기존 live FK `outfit_id`는 원본 hard delete 시 null이 되지만 출처/구성은 유지하고 재시도도 기존 기록을 반환한다. source ID는 현재 원본 조회를 보장하는 FK가 아니다. 기존 기록에는 두 출처 컬럼을 null로 유지하며 자동 추정/역산하지 않는다. 스냅샷 범위는 당시 의류 ID 집합이며 의류 이름/가격/사진 등은 현재 값을 읽는다.

`model.ts`는 지역 날짜 YYYY-MM-DD(1900-01-01–9999-12-31), 메모 5000자, 수동 ID 정규화/중복/최대 50개와 최대 366일의 포함 범위를 검증한다. `repository.ts`는 세션 검사/시작 토큰 고정/AbortSignal/자동 재시도 금지와 record/get/20개 range 페이지를 제공한다. 조회는 현재 코디가 아닌 wear_event_items를 중첩 조회하며 비활성/휴지통 의류 참조도 남긴다.

`queries.ts`는 회원별 기록/범위 key, 포커스 갱신, 15초 요청 취소, 해제/계정 경계 뒤 결과 폐기를 제공한다. 기록 뒤 해당 회원의 wear/wardrobe/outfits/insights 조회를 취소·무효화한다. 호출자는 하나의 기록 시도/재시도에 같은 이벤트 ID와 입력을 유지해야 한다.

H02: `/calendar`는 월 이동/날짜 직접 이동/오늘/날짜별 건수와 선택일 20개 목록을 제공한다. `/wear/new`에서 저장 코디나 활성 의류를 골라 기록하고 `/wear/[eventId]`에서 수정·삭제한다. `CalendarScreen`/`Pickers`/`FormScreen`/`EditScreen`을 사용한다. private 사진은 조회할 때만 발급하며 목록 사진은 기록당 앞 4개, 폼은 최대 50개 의류를 조회한다. 폼의 기본 날짜는 마운트 시 고정해 자정 이후 같은 계정의 재렌더가 초안을 초기화하지 않게 했다.

`update_wear_event`는 기본 keep 모드에서 날짜/메모만 바꾸고 당시 의류/출처를 유지한다. 기존 구성의 비활성/휴지통 상태는 keep 편집을 막지 않는다. items/outfit 모드를 명시하면 현재 본인 활성 의류/코디 버전을 다시 검사한 뒤 이 기록의 구성만 원자적으로 교체한다. updated_at CAS와 원하는 값의 무변경 재시도를 사용하며, timestamp는 단조 증가한다. 폼 snapshot은 백그라운드 조회로 덮어쓰지 않으며 실패·충돌 시 입력 유지/확인 후 최신 기록 교체를 제공한다.

`delete_wear_event`는 확인한 버전으로 soft delete하고 반복 요청은 기존 tombstone을 반환한다. 생성 재시도에 의한 되살림을 막기 위해 기존 생성 validator를 app_private로 옮겨 회원 실행 권한을 제거하고 공개 진입점에서 삭제 여부를 검사한다. deleted 이벤트/스냅샷은 DB에 남지만 목록/날짜별 건수/item_wear_stats/wardrobe_item_usage에서는 제외한다. 복원·영구 삭제는 제공하지 않는다.

`wear_day_counts`는 회원/RLS를 유지하는 날짜별 집계다. 화면은 현재 페이지와 독립적인 월 건수/선택일 목록을 사용한다. 생성·날짜 이동·구성 교체·삭제 뒤 같은 회원의 wear/wardrobe/outfits/insights 조회를 취소·무효화한다. 폼 이탈/최신 교체/삭제에는 확인을 연결했다. 회원 직접 테이블 쓰기는 계속 닫혀 있다. 최신 근거는 `docs/PHASE_11_VALIDATION.md`이며 실제 브라우저·실기기 검증은 사용자 요청으로 보류다.
