# 회원별 카테고리 관리

`/settings/categories`는 상단 **설정 → 카테고리 관리**에서 연다. 이전 `/categories` 주소는 새 경로로 이동한다. 기본 7종류의 이름·순서·사용 여부와 기존 세부 분류를 수정하고 세부 분류를 추가한다. PC는 왼쪽 옷 종류/오른쪽 세부 분류의 A안이다. 이름은 연필로 편집 후 저장하고 사용 여부 스위치는 즉시 저장한다. 순서 변경 모드에서 옷 종류는 화살표로, 세부 분류는 손잡이를 잡아 드래그해 바로 저장한다. 모바일은 상단 종류 선택으로 전환한다. 기본 종류 추가/부모 이동/영구 삭제는 제공하지 않는다.

공유 `categories`의 canonical slug와 코디 슬롯 관계는 유지한다. 회원 이름/순서/숨김은 `category_preferences`, 새 세부 분류는 본인 소유 `u_UUID` leaf에 저장한다. `member_categories(owner)`는 본인에게 유효한 이름/순서/사용 여부와 CAS 버전을 반환한다. 숨김은 새 옷 등록 선택지만 제한한다. 기존 옷 편집은 원래 분류를 유지하고 목록 필터와 코디 후보는 숨긴 분류의 기존 옷도 찾을 수 있다.

쓰기 RPC는 회원 잠금·형식/형제 이름 중복·부모/소유자·버전 검사를 수행한다. 순서 변경은 전체 형제 집합/기존 순서를 비교하고 원자적으로 저장한다. 이름 충돌 시 입력을 유지하며 명시적 변경 취소로 최신 값으로 돌아간다. UUID/같은 결과 재시도로 응답 유실 뒤 중복 생성을 막는다.

Query는 회원별이며 500개 단위로 전체 디렉터리를 읽는다. 쓰기는 시작 토큰에 고정하고 15초 중단/화면 해제·계정 전환 뒤 결과 폐기를 사용한다. 관련 카테고리/의류/코디/착용/통계 조회를 무효화한다. 다른 세션 변경은 재진입·포커스 시 재조회하며 실시간 구독은 없다. 화면 이탈/미저장 입력 경고를 연결했으며 실제 브라우저·실기기 확인은 보류다.

A안 적용과 검증은 `docs/CATEGORIES_A_VALIDATION.md`다. 내부 종류 변경에도 입력 폐기를 확인한다. 저장 결과를 개인 캐시에 반영하며 순서 변경 후에는 갱신된 버전까지 읽어 다음 변경에 사용한다.

세부 분류 드래그는 SortableCategoryList와 웹/네이티브 CategoryDragHandle 어댑터를 사용한다. 별도 라이브러리는 없으며 실제 행 높이/현재 순서로 좌표를 계산한다. 놓을 때 전체 순서를 한 번 저장하고 취소/무변경은 쓰지 않는다. 키보드/접근성 대체 조작과 실패 복귀를 연결했다. 검증은 `docs/CATEGORY_DRAG_VALIDATION.md`다.
