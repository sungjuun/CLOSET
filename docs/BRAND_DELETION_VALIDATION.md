# 브랜드 삭제와 이미지 맞춤 — 2026-10-29

## 사용

**설정 → 브랜드 관리 → 목록에서 브랜드 선택 → 브랜드 삭제 → 삭제 확인**으로 삭제한다. 확인 화면은 휴지통을 포함한 옷의 브랜드 이름/연결 해제와 이미지 삭제를 안내한다. 옷·의류 사진·코디·과거 착용 이벤트/구성은 삭제하지 않는다. 화면에서 브랜드 복원은 제공하지 않으며 같은 이름으로 새 브랜드 등록은 가능하다.

브랜드 이미지는 선택 시 원본 비율을 유지하며 중앙 정사각형으로 자동 crop/재인코딩한다. 미리보기와 카드/목록/상세 로고는 cover로 표시해 이미지와 프레임 비율 차이에서 생기는 띠 여백을 없앤다. 넓거나 긴 원본의 가장자리는 잘릴 수 있으며 저장 전 미리보기로 확인한다. 사진 자체에 포함된 흰 배경이나 투명 여백을 자동 식별/제거하는 기능은 아니다. 원본 파일과 기존 업로드 파일은 변경하지 않고 신규/교체 업로드에만 정사각형 변환을 적용한다. 일반 의류 사진은 기존 전체 비율 유지가 기본이다.

## 저장 계약

16번째 migration `20261029030000_brand_deletion.sql`을 로컬에 적용했다. brands.deleted_at과 활성 이름 partial unique index를 추가하고 직접 쓰기 금지/RLS를 유지했다. 삭제 RPC는 본인/updated_at CAS를 확인하고 연결 의류를 잠근 뒤 브랜드 필드 해제와 tombstone 기록을 단일 트랜잭션으로 처리한다. 의류가 다른 트랜잭션에서 수정 중이면 NOWAIT로 전체 작업을 거부하고 재시도 안내한다. 브랜드 이름 동기화도 같은 잠금 경합 방식을 사용한다.

삭제된 ID의 재등록·이미지 연결·새 업로드·의류 재연결을 거부한다. 삭제 재시도는 기존 tombstone을 반환해 응답 유실에 대응한다. 다른 회원과 익명 사용자의 삭제/파일 접근은 허용하지 않는다.

삭제 확인 후 해당 브랜드 폴더의 참조/미연결 이미지를 Storage API로 100개씩 정리한다. 삭제 직후 새 업로드를 거부하고 늦은 이미지 연결도 차단한다. 파일 정리 실패는 브랜드 삭제 성공과 구분해 안내하고 현재 화면에서 다시 정리할 수 있다. 네트워크 종료 등으로 남은 파일의 자동 서버 수거는 기존 후속 과제다. 본인 삭제 파일은 Storage 삭제 조회/재시도를 위해 정리 전까지 본인 읽기를 허용하며 타인 읽기는 계속 차단한다. 기존 signed URL은 파일 삭제 또는 만료 때까지 유효할 수 있다.

회원 수명의 토큰 고정/요청 취소와 브랜드·의류·코디·착용·통계 캐시 무효화를 사용한다. 새 패키지/환경 변수는 없다. 다른 PC의 로컬 DB에는 `npm run db:migrate`가 필요하고 원격에는 적용하지 않았다.
