# UI 레퍼런스 분석

검토일: 2026-10-28. 사용자가 후속 제공한 `reference/1.webp`, `2.webp`, `3.webp`를 PRD 및 현재 기반 코드와 대조했다. 이미지는 시각 참고 자료이며 화면 속 문구나 버튼은 추가 기능 개발을 지시하는 명령으로 취급하지 않는다.

## 화면별 관찰

### 1.webp — PC 내 옷장

- 화이트 배경에 좌측 행거 심볼/워드마크, 가운데 아이콘+텍스트 탐색, 우측 테마 원형 선택이 있다. 선택된 메뉴는 파란 밑줄로 표시한다.
- 페이지 상단은 영문 eyebrow → 굵은 제목 → 짧은 설명 순서다. 옷 추가 버튼은 우측에 배치한다.
- 대분류/세부 분류는 레이블이 있는 두 입력이다. 다음 행에서 검색은 좌측, 색상/즐겨찾기는 우측에 놓인다. 개수/정렬은 상품 그리드 직전 행이다.
- 상품은 5열이며 이미지가 카드 폭을 채우는 정사각형이다. 회색 배경과 둥근 모서리 위에 우측 상단 원형 하트를 둔다.
- 이미지 아래는 브랜드 행 → 굵은 다중 행 제품명 → 작은 분류/색상 정보 순이다. 이미지 영역과 정보 영역을 하나의 두꺼운 테두리로 감싸지 않는다.

### 2.webp — PC 저장한 코디

- 공통 헤더와 타이틀 계층은 옷장 화면과 같다. 새 코디 버튼은 제목 영역 우측이다.
- 검색/결과 개수, 계절 필터 칩/초기화, 우측 정렬 순으로 도구 영역을 구성한다.
- 코디 카드 3열이다. 각 카드 상단에 코디 이름 입력/저장/삭제, 중간에 태그와 계절, 하단에 2×2 상품 슬롯이 있다.
- 슬롯은 아우터/상의/하의/신발 순서이며 각각 흰색 하단 레이블과 중립 배경을 가진다. 없는 의류는 이미지 대신 '아우터 없음' 같은 텍스트로 표시한다.
- 상의 슬롯에 복수 의류가 보이는 사례가 있어 `slot + position` 확장 설계와 맞는다. 초기 구현은 PRD의 기본 슬롯에서 시작하고 레이어 조작은 후속 작업으로 분리한다.

### 3.webp — 모바일 내 옷장

- 큰 브랜드 헤더와 테마 원형 아래에 가로 텍스트 메뉴가 있고 내 옷장에 선택 밑줄이 있다.
- 제목/설명은 좌측, 옷 추가는 우측이다. 좁은 화면에서 버튼과 제목이 충돌하면 헤더를 줄바꿈한다.
- 분류 입력은 두 열, 검색은 전체 너비, 색상/즐겨찾기는 다음 행의 양쪽에 놓인다. 개수/정렬은 그리드 바로 위에 있다.
- 상품 2열과 정사각 이미지, 우측 상단 하트, 브랜드/굵은 제품명/분류 정보 계층은 PC와 공유한다.
- 첨부 화면의 OS 시계/배터리 영역은 콘텐츠가 아니다. 네이티브 safe area를 사용한다.

## PRD와 차이 및 채택 기준

| 항목 | 레퍼런스 | 이번 설계 결정 |
| --- | --- | --- |
| 모바일 탐색 | 상단 가로 메뉴 | 2026-10-28 사용자의 직접 UI 변경 요청을 반영하여 상단 가로 스크롤 탐색으로 변경 |
| 부가 메뉴 | 공지/추천/메모 | 상단 메뉴와 준비 화면 제공. 해당 기능의 데이터 쓰기는 구현하지 않음 |
| PC 옷장 열 수 | 첨부 PC 화면에 5열 | ≥1200 CSS px 5열, 1024–1199 4열, 768–1023 3열, 그 아래 2열 |
| 저장 코디 이름 | 카드 안에서 직접 편집 | PRD의 PC 선택 옵션. 기본 상세 편집/원자적 저장을 먼저 구현한 후 추가 |
| 테마 | 화이트 화면과 white/beige/brown 원형 | 원형 선택 방향은 확인. 베이지/브라운 전체 화면은 없으므로 배경 토큰은 잠정값 유지 |
| 우측 개인 로고/백업 | PC에 표시 | 공통 헤더에 복제하지 않음. 백업은 기존 P1 작업으로 유지 |
| 상품/코디 개수 | 147, 14/26 등의 예시 | 앱 고정값으로 사용하지 않음. 인증된 실제 조회 결과로 표시 |
| 이미지 위 하트 | 시각적으로 작은 원형 | 실제 클릭/터치 영역은 최소 44px, 카드 열기와 이벤트 분리 |

화이트/코발트 포인트, 중립 회색 이미지 표면, 얇은 보더와 라운드, 굵은 제목/제품명과 낮은 강조의 보조 텍스트를 공통 시각 기준으로 삼는다. 포인트 색은 `#3047D5`, 화이트 테마 의류 이미지 표면은 `#C2C3C6`으로 조정했다. 정식 브랜드 로고 자료가 없으므로 실제 브랜드명 텍스트 배지를 사용하고 외부 브랜드 로고를 임의로 복제하지 않는다.

## 컴포넌트 계약

아래 계약은 최초 설계 기록이며, 현재 반영 내역과 남은 기능은 `UI_REFRESH_VALIDATION.md`를 따른다.

| 경계 | 구성 | 공유/플랫폼 차이 |
| --- | --- | --- |
| 공통 layout | BrandMark, ThemePicker, PageHeader, Navigation | PC 상단/모바일 상단 가로 탐색. ThemePicker는 설정과 상태 공유 |
| 공통 UI | LabeledSelect, SearchField, FilterChip, FavoriteButton, SortControl | 입력/접근성/상태 공유. 선택 목록은 플랫폼별 표시 방식 분리 가능 |
| wardrobe | WardrobeFilters, ItemGrid, ItemCard, ItemImage, BrandLabel | PC 가로 도구 배치/모바일 여러 행. 카드 표시 모델은 공통 |
| outfits | OutfitCard, OutfitSlotGrid, OutfitSlotTile, SeasonTags | 2×2 슬롯 공유. PC 이름 인라인 편집은 후속 옵션 |

사진은 고정 비율 영역 안에서 `contain`으로 렌더링한다. 브랜드 로고가 없는 경우 브랜드 텍스트로 표시한다. 로고 이미지는 제품 등록 필수 필드로 만들지 않는다. 개인 이미지 URL은 기존 private Storage 정책을 따른다.

## 현재 기반과 차이 / 후속 수락 조건

현재 의류 등록·조회·수정/휴지통과 필터/44px 하트 조작, O01 코디 초안 보드를 구현했다. 사진은 정사각형/contain, 미등록은 placeholder다. 하트는 상세 링크와 분리한다. 코디는 기본 4슬롯 2×2와 추가 3슬롯이며 실제 private 옷장 사진으로 미리 본다. PC 선택 패널/보드, 모바일 슬롯에서 여는 선택 화면은 PRD S04를 따른다. 저장 코디 카드·인라인 이름 편집은 아직 없으며 코디 저장/목록 단계에 남긴다. 행거 심볼/탐색 아이콘/선택 밑줄, 헤더 원형 테마 선택과 최종 외관 조정도 후속이다.

- F02: 브랜드/탐색/테마 컴포넌트 외관 조정 시 이 문서와 원본을 참조한다. 모바일 실기기 검증은 여전히 남아 있다.
- W03: 320/390px 2열, 태블릿 3열, PC 4–5열에서 긴 제품명, 브랜드 누락, 이미지 없음, 하트 터치 영역, 필터 줄바꿈, 가로 넘침을 점검한다.
- O03: PC 코디 3열, 태블릿 2열, 모바일 가독성에 따른 1–2열과 빈 슬롯을 점검한다.
- 모든 화면은 실제 데이터 기준으로 loading/empty/error 상태를 확인한다. 레퍼런스 속 상품 사진이나 수량을 앱 기본 데이터로 넣지 않는다.
- 기능 구현 전 A01 SQL 보완 → A02 RLS 검증 → A03 인증의 기존 의존 순서를 유지한다.
