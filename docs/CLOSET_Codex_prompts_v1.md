# CLOSET. — Codex 구현 지시서 v1.0

이 파일과 `CLOSET_PRD_v1.md`, `CLOSET_schema_v1.sql`, 사용자가 제공한 이미지 3장을 Codex 프로젝트의 `docs/` 및 참조 자료에 넣고 사용.

## 1. 첫 요청 — 프로젝트 총괄 지시문

```text
너는 Expo/React Native Web, TypeScript, Supabase, PostgreSQL, UX/접근성에 숙련된 시니어 풀스택 엔지니어다.

프로젝트: CLOSET. (개인용으로 시작해 회원 서비스로 확장하는 디지털 옷장 관리 앱)
목표 플랫폼: PC 웹 + iOS + Android
디자인 기준: 제공한 CLOSET 화면 3장 (화이트 배경, #3155D9 블루 포인트,
PC 5열 상품 그리드, 모바일 2열, 저장 코디 4슬롯 카드, 브랜드/이름/색상 표시).

첨부된 docs/CLOSET_PRD_v1.md 와 docs/CLOSET_schema_v1.sql을 유일한 제품 요구사항의 출발점으로 삼아라.
불명확한 요구사항은 합리적인 기본값을 선택하되 결정은 docs/DECISIONS.md에 기록하라.

핵심 기술:
- Expo Router / React Native / React Native Web / TypeScript strict
- Supabase Auth + PostgreSQL + private Storage
- TanStack Query + Zustand + Zod
- 기본 한국어, 기본 KRW, white/beige/brown 테마
- 하나의 코드베이스, 필요 시 .web.tsx와 .native.tsx 분리

절대 지켜야 할 규칙:
1. P0부터 회원별 DB RLS를 사용하고 사용자 소유권을 클라이언트 필터만으로 보호하지 말 것.
2. SUPABASE_SERVICE_ROLE_KEY 및 API 비밀 키를 브라우저/앱 번들에 노출하지 말 것.
3. 사진은 비공개 버킷을 사용하고 사용자의 개인 폴더에서만 읽거나 쓸 것.
4. 입력값 검증, 로딩/빈 상태/오류 상태, 인증 세션 만료, 중복 클릭 방지를 처리할 것.
5. 모든 옷 이미지가 같은 비율로 보이되 사진은 왜곡하지 말고 contain으로 렌더링할 것.
6. 타인의 옷 사진·상표·상품 데이터를 무단 수집하지 말 것.
7. 코디를 수정한 이후에도 과거 착용 이력이 보존되는 데이터 구조를 유지할 것.
8. 테스트 없는 가짜 완료 보고를 하지 말 것. 실행하지 못한 테스트는 명확히 구분할 것.
9. 현재 작업과 무관한 파일 변경, 대규모 리팩터링, 불필요한 의존성 추가를 피할 것.
10. `.env.example`만 Git에 커밋하고 실제 비밀 값은 포함하지 말 것.

진행 방식:
- 먼저 저장소/설치 상태를 확인하고 기존 코드가 있으면 함부로 덮어쓰지 말 것.
- 현재 요구사항을 P0/P1/P2로 재정리한 구현 체크리스트를 docs/TASKS.md에 작성.
- 전체 작업을 순서가 명확한 작고 독립적인 단위로 쪼개라.
- 한 단계 구현 후 typecheck, lint, 관련 테스트를 실행하고 실패를 수정.
- 완료마다 변경 파일, 테스트 결과, 남은 과제, 다음 작업을 간단히 보고.
- 먼저 '1단계 환경설정/디자인 시스템/라우팅'부터 수행. 이후 단계는 의존성 순서대로 진행하되 기능 사이 경계에서 진행 상태를 기록하라.
```

## 2. 1단계 — 시작 구조 + 웹/모바일 셸

```text
CLOSET 1단계를 구현해줘.

- Expo Router + TypeScript strict 초기 세팅 또는 기존 프로젝트 정비.
- 주요 라우트: 로그인, 옷장, 저장 코디, 코디 만들기, 착용 기록, 통계, 설정.
- PC 상단 내비게이션, 모바일 하단 탭을 각각 구현.
- white/beige/brown 테마 토큰 및 설정 상태 구조.
- 원래 이미지를 픽셀 단위로 '복제'하기보다 레이아웃 계층, 여백, 그리드 비율을 참고.
- 320px/390px 모바일과 1280px/1440px PC 뷰를 점검.
- API 데이터가 없어도 개발 가능하도록 타입이 정확한 예시 fixture 제공; 배포 시 mock 비활성화.
- `.env.example`, README 개발 실행 방법, 기본 lint/typecheck/test scripts.

완료 조건: 웹과 모바일에서 라우팅이 되고, 화면 크기에 따라 다른 탐색 UI가 보이며, 불필요한 가로 스크롤이 없다.
```

## 3. 2단계 — DB/인증/보안

```text
CLOSET 2단계를 구현해줘.

- docs/CLOSET_schema_v1.sql을 Supabase migration 파일로 정리.
- 적용 전 SQL 문법/버전 호환성 검토. 로컬 또는 별도 테스트 DB에서 실행 검증.
- 이메일 로그인/회원가입/로그아웃/세션 복원.
- RLS 및 개인 사진 Storage bucket 정책 적용.
- user_id가 다른 계정 소유의 wardrobe_items, item_images, outfits,
  outfit_items, wear_events에 접근할 수 없음을 통합 테스트.
- 다른 회원의 item_id를 내 코디에 연결하는 INSERT/UPDATE도 실패해야 함.
- 로그인 교체 시 React Query 캐시가 다른 계정에 넘어가지 않도록 초기화.
- 개발 문서에 필요한 Supabase 환경 변수를 기록. 실제 키를 출력/커밋하지 말 것.

완료 조건: 2개 테스트 계정 데이터가 서로 완전히 분리되고, 익명 접근이 차단된다.
```

## 4. 3단계 — 내 옷장 P0

```text
CLOSET 3단계를 구현해줘.

- 상품 카드/브랜드·이름·카테고리·색상·즐겨찾기 UI.
- 의류 직접 등록/상세/수정/보관/soft delete.
- 사진 0~5장, 대표 이미지 지정, JPEG/WebP 변환과 업로드 실패 복구.

- 대량 데이터를 대비한 페이지네이션 또는 무한 스크롤.
- 배포 코드에서 데모 고정 데이터를 사용하지 말고 Supabase 실제 CRUD 연동.

완료 조건: PC에서 새 아이템 저장 → 모바일 동일 계정에 표시, 다른 계정에는 비공개.
```

## 5. 4단계 — 코디 만들기 / 저장한 코디 P0

```text
CLOSET 4단계를 구현해줘.

- 옷장 아이템 검색/선택 UI에서 코디 보드 슬롯에 의류 배치.
- 아우터/상의/하의/신발 기본 4슬롯, 가방·액세서리 확장 가능한 설계.
- PC에는 옷장 패널+코디 보드를 나란히, 모바일에는 보드+아이템 선택 패널.
- 저장된 코디 카드에 2x2 이미지와 계절/태그, 즐겨찾기 표시.
- 이름/메모/계절 편집, 생성/저장/복제/삭제.
- 다중 테이블 저장(outfits + outfit_items)은 원자적 RPC/트랜잭션으로 처리.
- 이미 보관/삭제된 아이템은 코디에 상태 경고를 표시하고 선택 제한.

완료 조건: 코디를 저장/재편집/재조회해도 슬롯과 아이템 연결이 정확하다.
```

## 6. 5단계 — 착용 기록 / 통계 P1

```text
CLOSET 5단계를 구현해줘.

- 월별 착용 달력, 선택일의 착용 기록 생성/수정/삭제.

- 코디 아이템 목록을 저장 순간 wear_event_items에 기록.
- 30일/90일/전체 누적 착용 횟수, 마지막 착용일, 한 번도 기록되지 않은 옷,
  가장 많이 입은 옷, 착용당 비용(0회 시 '계산 불가') 구현.

- 같은 날짜의 여러 착용 이벤트 지원.

완료 조건: 코디를 바꿔도 이전 날짜 기록은 그대로이며, 기록 삭제 시 통계가 갱신된다.
```

## 7. 6단계 — 상품 링크 정보 추출 P1

```text
CLOSET 6단계를 구현해줘.

- 사용자가 HTTPS 상품 URL을 제출할 수 있는 입력 UI와 확인 화면.
- import_jobs 테이블을 활용해 상태를 추적.
- 서버 측에서 공개적으로 이용 가능한 메타데이터(OG, JSON-LD)를 검토하여
  제품명/브랜드/가격/이미지 후보를 추출.
- SSRF 방지: http/https 중 정책에 맞게 https만 허용, localhost/사설망 차단,
  리다이렉션 재검증, 최대 응답 크기/시간 제한, 허용 MIME 확인.
- 접근 제한 우회, 로그인 세션 탈취, 이용조건에 반하는 수집 금지.
- 실패/차단/미지원 사이트는 수동 등록으로 전환.
- 추출 결과는 사용자 확인 전 자동 저장 금지.
- 이미지 사용/저작권 문제로 우선 메타데이터만 가져오는 방식 구현.
- AI API는 필수 아님. 추가 시 유료 호출 상한과 서버 전용 키 사용.

완료 조건: 지원/미지원 URL 모두 안전하게 처리하고 실패해도 사용자가 등록을 완료할 수 있다.
```

## 8. 7단계 — 공개 베타 준비 P2

```text
CLOSET 공개 베타 준비를 구현/점검해줘.

- 신규 가입 제한/초대 흐름 및 회원 탈퇴 시 DB와 이미지 삭제.
- 개인정보 안내, 약관/정책 문서 라우트, 문의/오류 신고.
- 데이터 내보내기/복원 테스트, 로그에 개인정보가 남지 않는지 점검.
- 타 사용자 데이터 접근, 저장소 접근, 직접 URL 접근 공격 테스트.
- 계정당 업로드 제한, 요청 제한, 서버 사용량 모니터링, 비용 통제.
- 공개 코디 공유는 기본 비활성화; 별도 승인과 라이선스 검토 전 출시 금지.
- 모바일 정식 스토어 등록용 서명/개인정보/심사 준비 절차 문서화.

완료 조건: 신규 회원을 초대해도 다른 사람의 사진/메모/가격이 노출되지 않는다.
```

## 10. 중요한 진행 팁
- 1~2단계는 High 수준의 추론과 테스트를 권장(아키텍처·보안 설계).
- 3~4단계 반복 UI 조정은 Medium으로도 진행 가능하나 코드 변경이 크면 High.
- 기능 전체를 한 번에 구현하라는 프롬프트보다 단계별로 검증 후 이어가기.
- Codex가 실제 이미지를 참고할 수 있도록 참조 스크린샷 3장을 프로젝트 내부 `docs/reference/`에 넣어라.
- Supabase 프로젝트 URL/publishable key는 프로젝트 설정에서 제공해야 함. `service_role` 키는 채팅·클라이언트에 노출하지 않는다.
