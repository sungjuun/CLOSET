# 11단계: 월 달력과 착용 기록 CRUD

검증일: 2026-10-28 (Asia/Seoul). H02 월 달력/선택일 목록/기록 등록·수정·삭제 화면과 RPC를 구현하고 코드·DB·번들로 검증했다. 브라우저·실기기 검증은 사용자 요청으로 보류를 유지했다. Q01 전체를 완료로 표시하지 않는다.

## 화면 연결

- `/calendar`: 월 이동, 날짜 직접 이동, 오늘, 6주 달력의 날짜별 기록 수, 선택일의 20개 페이지 목록과 빈/로딩/오류/재시도. 윤년·월말 날짜 보정, 1900년/9999년 경계를 처리한다. 월 건수는 현재 목록 페이지와 독립적으로 조회한다. 로딩/오류 때 건수를 실제 0으로 표시하지 않는다.
- `/wear/new`: 날짜·메모와 저장 코디 또는 활성 개별 의류 선택. 코디는 이름/태그/브랜드 검색과 12개 페이지, 의류는 이름/브랜드/색상 검색·종류·즐겨찾기와 20개 페이지를 제공한다. 선택된 옷은 별도 조회/사진/상태 표시와 제거를 제공한다. 같은 날 여러 기록을 남길 수 있다.
- `/wear/[eventId]`: 기록된 구성을 기본으로 유지하고 날짜/메모를 수정한다. 옷이 비활성/휴지통이어도 keep 편집을 허용한다. 사용자가 다른 코디/개별 의류로 교체를 선택할 때만 새 구성을 현재 상태로 검증한다. 오래된 원본 코디 버전을 자동으로 갱신하지 않고 사용자가 목록에서 다시 선택하게 한다.
- 폼은 최초 snapshot을 유지해 배경 조회가 입력을 덮어쓰지 않는다. 실패/충돌 때 입력 유지, 확인 후 최신 내용 교체, 삭제 확인, SDK 화면 이탈/공통 메뉴 확인을 연결했다. 저장·삭제 후 해당 날짜 달력으로 복귀한다. 날짜 기본값은 마운트 시 고정해 자정 이후 재렌더로 초안을 초기화하지 않는다.
- 목록 사진은 이벤트당 앞 4개, 폼은 최대 50개 의류를 조회해 조회 URL/사진 범위를 제한한다. private signed URL을 기록이나 초안에 저장하지 않는다. 회원 교체는 route key/Query key/요청 취소·토큰 고정 경계를 사용한다.

## DB와 데이터 계약

- `20261028080000_wear_calendar.sql`을 로컬 Supabase에 적용하고 실제 DB 타입을 재생성했다. migration은 총 11개다. reset/원격 배포나 새 패키지·환경 변수·외부 서비스 추가는 없다.
- `update_wear_event`: 이벤트별 advisory/행 잠금과 읽은 updated_at 원문으로 충돌을 검사한다. keep은 날짜/메모만 수정하고 스냅샷/출처를 보존한다. items/outfit은 현재 본인 활성/미삭제 의류 1–50개와 코디 버전을 잠금 안에서 검사하고 이 기록의 스냅샷만 원자적으로 교체한다. 현재 원하는 값이 이미 저장돼 있으면 무변경 성공으로 처리한다. timestamp는 clock_timestamp와 이전 값+1μs 중 큰 값으로 증가한다.
- `delete_wear_event`: 확인한 버전의 이벤트를 soft delete한다. 반복 요청은 기존 tombstone을 반환한다. 스냅샷과 출처를 남기며 복원/영구 삭제 API는 제공하지 않는다. 기존 생성 validator를 app_private로 옮겨 authenticated/PUBLIC/anon 실행을 거부하고 공개 생성 wrapper가 삭제된 ID의 재생성을 차단한다.
- `wear_day_counts`: security invoker/회원·RLS를 유지하는 일별 집계다. 날짜 포함 범위 최대 366일, 실제 월 범위를 서버에서도 검사한다. `item_wear_stats`와 `wardrobe_item_usage`는 삭제된 이벤트를 제외해 착용 횟수·마지막 착용일·착용당 비용·의류 참조 수를 함께 갱신한다. 일반 회원의 테이블 직접 쓰기는 계속 차단한다.
- 기록 쓰기 뒤 해당 회원의 wear/wardrobe/outfits/insights Query를 취소·무효화한다. 날짜 변경은 기존 월/새 월 집계를 모두 갱신할 수 있도록 wear prefix 전체를 무효화한다. 요청은 시작 토큰/15초 취소/해제 epoch를 사용하고 서버 commit 취소를 보장한다고 취급하지 않는다.

기존 Node 24.22.1/npm 11.19.1 환경을 사용했다. 권장 Node 22.23.x/npm 10 검증과 구분하며 package.json/lockfile은 변경하지 않았다. 테스트는 loopback 및 직접 생성한 임시 두 계정/데이터만 사용했다. 실제 계정/개인 사진은 사용하지 않았다. 종료 후 auth.users/wardrobe_items/outfits/wear_events/wear_event_items/item_images/storage.objects 모두 0건을 확인했다. 로컬 Supabase는 실행 상태로 유지한다.

다음은 I01 기간별 통계 화면/집계다. 현재 변경은 기존 착용당 비용 view의 삭제 제외까지이며 통계 화면은 여전히 준비 화면이다. O02–O03/H02 UI, Q01 기기간 갱신·접근성·실기기 확인과 원격 HTTPS/SMTP/배포는 남아 있다. 좁은 화면의 날짜 터치 영역·필터/확인창·키보드·스크롤·새로고침 이탈 경고는 실제 UI 검증에서 확인해야 한다. browser 도구 접근이나 재승인 요청은 하지 않았다.
