# 저장한 코디 레퍼런스 반영 — 2026-10-29

사용자가 제공한 카드 목록 이미지에 맞춰 저장한 코디 화면을 정리했다.

- 상단은 검색/결과 개수, 계절 버튼/필터 초기화/정렬의 두 줄이다. 별도 브랜드·태그·즐겨찾기 필터 UI는 제거하고 이름·브랜드·메모·태그 통합 검색을 유지한다. 검색창의 맨 앞 `#`는 태그 표기로 받아들이고 뒤의 텍스트를 검색한다. 이름 중간의 `#`와 검색 특수 문자는 그대로 유지한다.
- 카드 헤더는 이름 입력 + 저장 + 휴지통 한 줄이며 태그/계절 아래에 아우터·상의·하의·신발 2×2 보드를 표시한다. PC 1024px 이상 3열, 700px 이상 2열, 작은 화면 1열이다. 의류 사진은 contain을 유지하며 슬롯 프레임 내부의 중복 여백과 둥근 모서리만 정리했다.
- 별도의 보기·수정 텍스트 링크 대신 보드의 각 슬롯을 누르면 해당 코디 편집 화면을 연다. 추가 구성은 별도 링크로 표시한다. 삭제 확인창/중복 요청 방지/옷·과거 착용 기록 보존은 유지한다.
- 이름 편집 중 읽은 버전을 고정한다. 저장 실패 시 입력을 유지하며 취소하면 최신 서버 이름으로 돌아간다. 서버가 변경됐으면 충돌을 알리고 다시 확인하도록 한다. 저장 안내는 헤더 라벨에 표시해 카드의 높이를 바꾸지 않는다.

## 이름만 변경하는 RPC

`20261029040000_outfit_rename.sql`은 `rename_outfit(id, expected, name)`을 추가한다. authenticated만 실행하며 auth.uid() 소유자/미삭제/이름 1–160자/updated_at을 검사한다. 기존 코디 쓰기와 같은 advisory lock 및 행 잠금을 사용한다. 이름과 갱신 시각만 바꾸며 의류·레이어·메타데이터·착용 참조는 건드리지 않는다. 현재 이름이 요청과 같으면 응답 유실 재시도를 무해하게 처리한다. 상태가 바뀐 의류를 포함한 코디도 이름은 변경할 수 있다. DB 직접 쓰기 권한은 열지 않았다.

로컬 DB에 migration을 적용하고 생성 타입을 갱신했다. 다른 PC에서 받으면 `npm run db:migrate`가 필요하다. 추가 환경 변수/패키지는 없다.
