# 브랜드 등록과 의류 선택

검증일: 2026-10-28 (Asia/Seoul). 사용자 요청에 따라 브랜드명을 직접 반복 입력하던 의류 폼을 회원별 브랜드 목록 선택으로 변경했다. 브라우저·실기기 검증은 기존 요청대로 보류한다.

## 사용 흐름

1. 상단 메뉴 **브랜드** 또는 **내 계정 → 브랜드 관리**에서 브랜드명과 선택 사항인 이미지를 입력하고 **브랜드 저장**을 누른다. 이미지 미리보기·선택 취소, 이름/이미지 수정과 등록 이미지 삭제를 제공한다.
2. **옷 추가 / 옷 정보 수정 → 브랜드**에서 이름·이미지가 있는 목록을 검색해 선택한다. 선택 안 함도 가능하다. 선택창은 20개 페이지를 제공한다.
3. 옷장 카드·의류 상세에서 브랜드 이름과 이미지를 확인한다. 브랜드명을 수정하면 연결된 의류(휴지통 포함)의 이름도 함께 갱신되어 기존 검색·필터·통계에 반영된다.

브랜드명은 앞뒤 공백을 제거한 1–120자이며 계정 안에서 같은 이름을 중복 등록하지 않는다. 대소문자가 다른 이름은 별개다. 기존 의류의 비어 있지 않은 브랜드명은 migration에서 회원별 목록으로 옮기고 ID를 연결한다. 기존 DB/API 호환성을 위해 연결 ID가 없는 브랜드 텍스트는 보존하지만 새 앱 폼은 목록 선택을 사용한다. 브랜드 전체 삭제는 제공하지 않는다.

## DB·사진·세션 계약

- `20261028100000_brands.sql`: 총 13개 migration. `brands`에 회원별 RLS와 읽기 권한만 부여하고 쓰기는 인증된 `save_brand`/`set_brand_image` RPC로 제한한다. 의류의 `(brand_id,user_id)` 복합 FK와 trigger가 타인 연결을 막고 DB의 정식 이름을 채운다.
- 브랜드명 수정과 연결 의류 이름 갱신은 한 트랜잭션이다. 버전 CAS·브랜드 잠금·동일 결과의 무변경 재시도를 사용한다. 이름 저장과 이미지 저장은 별도 단계다. 이름 저장 후 이미지 실패 시 그 상태를 화면에 알리고 같은 이미지 작업으로 재시도한다.
- 로고는 `brand-private` 비공개 bucket의 `{owner}/brands/{brandId}/{imageId}.ext` 경로를 사용한다. 기존 플랫폼 이미지 선택/디코딩·재인코딩 어댑터를 재사용해 최대 2048px/5MiB JPEG·PNG·WebP로 변환한다. 서버는 소유 브랜드·경로·업로드 객체·크기/MIME 메타데이터를 검증한다. 서버 바이너리 디코딩은 기존 사진 기능과 마찬가지로 별도 과제다.
- 덮어쓰기/이동 권한은 없다. 새 UUID 경로를 업로드한 뒤 버전 확인으로 연결한다. 현재 참조 중인 로고의 직접 파일 삭제는 거부한다. 교체/해제 뒤 이전 파일을 정리하고, 정리 실패는 저장 성공과 구분해 알린다. 중단/실패로 생긴 미연결 파일의 자동 수거는 후속 과제다.
- 로고 signed URL은 60초이며 화면에서 45초마다 재조회하고 영구 저장하지 않는다. 세션 토큰 고정·AbortSignal·회원별 캐시/화면 key를 적용한다. 목록은 500개씩 끝까지 읽어 API 행 제한을 피하며 보이는 페이지/선택 브랜드만 signed URL을 요청한다. 브랜드 쓰기는 brands/wardrobe/outfits/insights 조회를 취소·무효화한다.
- 브랜드 폼의 미저장 이동/입력 초기화와 이미지 삭제는 확인을 연결했다. 실제 대화상자·파일 선택창·기기 뒤로 가기/레이아웃 검증과는 구분한다.
