# 9단계: 저장 코디 검색·필터

검증일: 2026-10-28 (Asia/Seoul). O03 이름·메모 검색을 태그·구성 브랜드로 확장하고 브랜드/태그/즐겨찾기 필터, 최근 수정순을 연결했다. O02 저장·수정·복제·삭제는 `PHASE_08_VALIDATION.md`를 따른다. 실제 브라우저 UI·네이티브 실기기 검증은 남아 있다.

## 구현과 검색 계약

- `20261028060000_outfit_search.sql`을 로컬 Supabase에 적용했다. migration은 총 9개이며 기존 데이터를 reset하지 않았다. 타입은 실제 DB에서 재생성했다. 새 패키지/환경 변수/외부 서비스는 없다.
- `search_outfits`는 `setof outfits` 반환형의 stable/security invoker 읽기 RPC다. auth.uid()와 요청 owner 일치/RLS를 유지하며 본인 미삭제 코디만 반환한다. PUBLIC/anon 실행 권한은 제거했다. 검색어/필터는 바인딩 값이고 동적 SQL이나 PostgREST 필터 문법으로 조합하지 않는다.
- 검색창은 이름·메모·각 태그·각 구성 의류 브랜드의 대소문자 무시 부분 일치다. `strpos`를 사용해 `%`, `_`, 쉼표·따옴표·역슬래시는 문자 그대로 처리한다. 검색어 앞뒤 공백만 제거하며 길이는 200자로 제한한다.
- 브랜드/태그 드롭다운은 정확 일치다. 검색어/브랜드/태그/계절/즐겨찾기는 AND 조건이다. 여러 구성 의류가 검색에 맞아도 EXISTS로 한 코디만 반환하고 집계한다. 검색된 의류만으로 카드를 잘라내지 않고 해당 페이지 코디의 전체 중첩 구성을 반환한다.
- 브랜드는 저장 당시 스냅샷이 아닌 현재 구성 의류의 값이다. 추가 가방/액세서리 슬롯과 보관·판매·기부된 의류도 포함한다. 휴지통 의류의 브랜드, 삭제 코디, 연결되지 않은 의류는 검색/브랜드 선택지에 포함하지 않는다. 기존 삭제 의류의 중첩 참조는 경고 표시를 위해 계속 조회할 수 있다.
- `outfit_filter_options`는 본인 전체 미삭제 코디의 브랜드/태그를 정렬·중복 제거해 반환한다. 현재 필터/페이지와 독립적이다. 선택한 값이 변경/삭제로 사라져도 그 필터는 유지하고 사용자가 바꾸거나 초기화할 수 있게 한다. 선택지 조회 실패는 별도 재시도 안내를 제공하며 검색/계절/즐겨찾기를 막지 않는다.
- 최근 추가/최근 수정/오래된 추가/이름순을 서버에서 정렬하고 ID로 동률을 해소한다. 12개 서버 페이지와 필터 결과 수/회원 전체 개수를 유지한다. 다른 세션에서 마지막 페이지가 삭제되면 HEAD 재집계 후 현재 개수를 반환하고 화면은 마지막 유효 페이지로 보정한다.
- 필터 변경/초기화는 페이지를 0으로 돌린다. 이름 검색은 기존 350ms debounce를 유지한다. Query key에는 회원/페이지와 정규화한 모든 조건을 넣는다. 코디 변경 뒤 코디/옷장을, 의류 변경 뒤 옷장/코디를 무효화해 브랜드/삭제/복원 변경이 검색/선택지에 반영되게 했다.

새 단위 3개는 필터 입력 경계, 페이지 초기화/조건 보존/빈 결과 분기, 회원·페이지·모든 필터의 캐시 경계를 검증한다. 코디 목록 통합은 기존 3개에서 10개로 늘었으며 기존 저장/선택/Auth/Storage/의류 회귀를 함께 통과했다. 300개는 API 기능 검증이며 운영 부하/브라우저 렌더링 성능을 완료했다고 주장하지 않는다.

기존 Node 24.22.1/npm 11.19.1 환경을 사용했다. 프로젝트 권장 Node 22.23.x/npm 10으로의 추가 검증은 수행하지 않았다. package.json/lockfile은 변경하지 않았다. 검증 실패에서 테스트용 상대 import를 보완했고 태그 정렬 기대값을 실제 문자열 정렬 순서에 맞게 수정한 뒤 전체 검증을 통과했다.

통합 테스트는 loopback 54321과 직접 생성한 임시 회원/데이터만 사용했다. 종료 후 auth.users/wardrobe_items/outfits/outfit_items/item_images/storage.objects 모두 0건을 확인했다. 기존 계정이나 개인 사진은 사용하지 않았다. 로컬 Supabase는 실행 상태로 유지한다.

## 재현과 다음 작업

```powershell
npm run db:migrate
npm run db:types
npm run check
npm run db:test
npx supabase db lint --local --level warning
npm run export:web
npm run export:native -- --output-dir dist/native
node scripts/check-public-bundle.mjs
```

다음은 O02–O03 브라우저 UI 검증과 Q01 실제 사용 전 회귀다. 320/390/1280/1440px의 새 필터/초기화/선택지 오류/즐겨찾기 빈 결과/최근 수정순/페이지 보정, 저장→수정→복제→삭제와 미저장 이탈/충돌 확인창을 실제로 확인해야 한다. 네이티브 기기·기기간 갱신·접근성 보조기기, 원격 HTTPS/SMTP/배포도 남아 있다. Realtime 구독이나 새로고침 후 필터 복원/URL 공유는 이번 범위에 추가하지 않았다.
