# 분할 탐색형 설정 — 2026-10-29

선택한 분할 탐색형 목업을 실제 설정 페이지에 적용했다. 사용자가 추가 범위로 선택한 기본 정렬·카드 밀도·프로필 이름을 구현했으며 백업·복원 메뉴는 이번 범위에 포함하지 않는다.

## 화면과 동작

- PC는 왼쪽 분류와 오른쪽 상세 패널이다. 일반 / 옷장 관리 / 기록·통계 / 계정·보안을 제공한다. 900px 미만에서는 분류를 상단 2열 버튼으로 배치한다.
- 일반: 기존 계정 테마를 미리보기 카드로 선택한다. 옷장·코디 기본 정렬과 카드 밀도는 계정에 자동 저장한다. 기존 한국어/원화 정책을 유지한다.
- 옷장 관리: 기존 카테고리·브랜드·의류 휴지통으로 연결한다. 기록·통계: 착용 달력과 통계 화면으로 연결한다.
- 계정·보안: 본인 이메일 표시, 프로필 이름 저장/취소, 기존 비밀번호 재설정과 로그아웃을 제공한다. 프로필 이름은 헤더와 설정 사이드바에도 표시한다. 빈 이름은 기본 표시로 돌아간다. 미저장 이름은 메뉴·페이지 이동/로그아웃 시 폐기 확인을 한다.
- 목록 기본 정렬은 새 목록 진입에 적용한다. 사용자가 해당 화면에서 수동으로 선택한 정렬은 유지하고, 필터 초기화하면 저장된 기본값으로 돌아간다. 목록에서 임시로 고른 정렬은 계정 기본값을 변경하지 않는다.
- 카드 밀도는 두 목록의 열 수를 화면 너비에 맞춰 변경한다. 기존 밀도는 기본값이다. 1280px 옷장은 기본 5 / 촘촘하게 6 / 여유롭게 4열, 코디는 3 / 4 / 2열이다. 휴대폰 코디는 1열을 유지한다. 옷 사진 원본과 contain 표시 정책은 바꾸지 않는다.

## 저장과 회원 경계

`20261029050000_account_preferences.sql`은 profiles에 wardrobe_sort / outfit_sort / card_density를 추가한다. 기존 profiles.display_name을 사용하며 새 값은 enum CHECK로 제한한다. 본인만 읽는 기존 RLS를 유지하고 새 컬럼의 직접 UPDATE 권한은 열지 않는다.

`save_account_preferences(p_patch,p_expected)`는 auth.uid() 소유자만 행 잠금을 잡고, 수정하는 필드의 이전 값을 비교해 저장한다. 이름은 공백 정리 후 최대 80자, 빈 이름은 null이다. 수정 필드 외의 테마·통화·다른 설정은 잠긴 현재 값을 보존한다. 같은 필드의 충돌은 40001, 이미 원하는 값인 재시도는 허용한다. 다른 필드/테마를 동시에 바꾸어도 덮어쓰지 않는다.

계정별 Query key와 인증 범위 Provider를 사용한다. 로그아웃/계정 교체 시 상태와 요청을 폐기하고, 작업 시작 토큰을 고정한다. 읽기·쓰기는 15초에 중단한다. 저장 중 중복 요청과 포커스 재조회를 막고, 완료 시 이전 조회를 취소한 뒤 확인된 결과를 캐시에 넣는다. 실패/응답 유실은 재조회로 확인하되 이름 초안의 예상 값을 조용히 덮어쓰지 않는다. 오프라인 신규 실행은 기본 정렬/밀도를 사용하며 재연결 후 계정 설정을 다시 읽는다.

로컬 migration과 생성 타입을 적용했다. 다른 PC에서는 최신 소스의 `npm run db:migrate`가 필요하다. 추가 패키지/외부 서비스/환경 변수는 없다.

- TypeScript/ESLint 및 단위 116개 통과.
- 실제 로컬 DB 전체 회귀 126개 통과(Node 13 + Vitest 113). 설정 통합 8개는 기존 테마 4개와 새 설정 4개다. 새 설정의 로그인 복원, 다른 회원/익명/직접 쓰기 차단, enum/이름 검증, 수정 필드 충돌/독립 필드 동시 변경, 응답 유실 재시도, 취소와 시작 토큰 고정을 검사한다.
