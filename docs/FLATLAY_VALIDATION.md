# 실제 의류 사진 플랫레이

2026-10-30 사용자 후속 요청. 직전의 격자 나열형과 샘플 마네킹을 대체한다.

## 동작과 호환성

- 추천 카드와 기존 코디 편집의 이미지 표현에서 마네킹 선택/체형/샘플 SVG 생성기를 제거했다. 추천·고정·교체·저장·원본 의류 ID·회원 분리는 유지한다.
- `flatlay.ts`의 동일한 900×1100 좌표를 미리보기와 PNG가 사용한다. 아래쪽 하의 위에 상의/아우터를 두고 가방은 왼쪽, 액세서리는 오른쪽, 신발은 하단에 기울여 배치한다. 없는 슬롯은 그리지 않는다. 그림 대신 실제 의류 사진만 사용한다.
- 기존 슬롯 격자·사진 테두리·브랜드/이름 텍스트는 이미지 안에서 제거했다. 코디 이름·점수·옷 정보와 교체 버튼은 카드에 계속 표시한다. 미등록 사진은 해당 위치에 안내를 넣는다.
- 가장자리와 연결된 밝고 균일한 배경만 클라이언트에서 투명 처리한다. 투명 여백을 줄인 뒤 contain으로 넣어 옷의 원래 비율과 픽셀 경계를 유지한다. 흰색 내부 영역·기존 alpha를 보존하며 복잡한 배경/판단이 불확실한 사진은 원본을 유지한다. 이는 AI 누끼가 아니며 모든 배경을 완벽하게 제거한다고 보장하지 않는다. 투명 제품 PNG는 그대로 사용할 수 있다.
- 웹은 canvas, 네이티브는 기존 ImageManipulator와 `fast-png` 8.0.0을 사용한다. 처리용 캐시 파일은 정리하고 원본 Storage 파일은 수정하지 않는다. 변환 사진은 회원별 메모리 캐시에서 카드 간 공유하며 URL의 만료 서명을 캐시 키에 남기지 않는다. 로그아웃 시 기존 private 캐시 정리 경계를 따른다.
- 렌더러/캡처 대상은 나열형 하나만 남겼다. 새 저장은 `items`, `regular`(기존 필수 호환 필드), `item-board`로 고정한다. 기존 DB enum/과거 파일은 삭제하지 않았으며 과거 마네킹 설정의 코디도 실제 사진 플랫레이로 열리고 재저장한다. 기존 구도 PNG는 재생성 전까지 과거 파일로 보존한다. 새 migration/외부 API/유료 호출/환경 변수는 없다.

## 검증

- strict TypeScript, 경고 없는 lint 및 단위 182개 통과. 기존 마네킹 테스트 3개는 제거된 동작에 따라 대체했고 플랫레이 좌표/회전 경계, 이미지 비율·텍스트 escape, 단색 배경/흰 옷/복잡한 배경/기존 alpha/불확실 결과/원본 불변 테스트 6개를 추가했다.
- 실제 로컬 Supabase의 추천 통합 8개 통과. 기존 ID/회원 격리/경로·덮어쓰기 제한/응답 유실/버전 및 과거 표현 설정 호환성을 유지한다. DB 정책이나 기존 RPC를 변경하지 않았다.
- 브라우저 1280px, 390px, 320px에서 미리보기 확인. 모바일 문서 너비는 viewport와 동일하다. 실제 등록 사진 5장의 복사본을 별도 임시 계정에만 넣어 원본 비율·배경 정리·겹침 배치를 확인했다. 원래 의류/사진은 읽기만 했다.
- 코디와 PNG 저장 및 PNG 다운로드 확인. 다운로드 900×1100 이미지를 직접 열어 미리보기와 같은 구도와 온전한 옷 가장자리를 확인했다.
- 임시 코디에 과거 mannequin/broad 설정을 넣고 기존 편집기를 열었을 때 관련 UI 없이 플랫레이만 표시되는 것을 확인했다. 표현 이미지 재저장 후 items/regular와 ready item-board 파일을 DB에서 확인했다. 브라우저 오류 로그 없음.
- Android/iOS JS export 성공. 실제 네이티브 기기의 화면 캡처·공유 시트 및 복잡한 실사 배경의 자동 분리는 후속 검증 범위다.

검증용 계정/파일은 정확한 fixture 소유자 경로로 정리하며, 저장된 원래 사용자 코디/이미지는 자동 변환하거나 덮어쓰지 않는다.
