# CLOSET. — 제품 요구사항 명세서 (PRD) v1.0
작성 기준: 2026-10-28 / 한국어 / PC 웹 + iOS + Android

> 목표: 개인용으로 먼저 사용하고, 안정화 후 회원을 초대할 수 있는 디지털 옷장 관리 서비스.
> 시각 디자인 레퍼런스: 사용자가 제공한 CLOSET 스크린샷 3장(화이트 배경, 코발트 블루 포인트, PC 다열 그리드, 모바일 2열 카드, 저장한 코디 4슬롯 카드).

## 0. 확정된 의사결정
- 1차 개발: 단일 Expo Router / React Native / React Native Web 프로젝트 + TypeScript.
- 데이터: Supabase Auth, PostgreSQL, Storage. P0부터 다중 사용자 데이터 분리/RLS.
- 초기 운용: 개인용 비공개. 향후 초대 기반 베타, 그다음 공개 회원가입.
- 의류는 수동 등록 필수, 링크 분석/AI 기능은 실패해도 앱 핵심 기능에 지장 없도록 독립 구현.
- 웹·앱에서 동일 계정/동일 데이터. UI 레이아웃은 PC와 모바일에 맞게 분기 가능.
- 등록한 옷과 코디는 기본 비공개. 공개 코디 공유는 별도의 명시적 동의를 거쳐 추후 도입.
- 서비스 통화 기본 KRW, 국제화를 위한 currency 칼럼 사전 확보.

## 1. 목표 및 성공 기준
### 핵심 사용자 스토리
1. 사용자는 집에서 PC로 옷을 등록하고 외출 중 스마트폰에서 같은 옷을 찾는다.
2. 사용자는 보유한 옷만 선택해 코디를 만든다.
3. 사용자는 특정 날짜에 입은 옷을 기록한다.
4. 사용자는 옷을 얼마나 활용하는지 착용 횟수/착용당 비용/미착용 리스트로 판단한다.
5. 사용자는 구매하려는 옷이 이미 보유한 옷과 중복되는지 확인한다.

### P0 완료 조건
- 이메일 회원 로그인 후 본인 데이터만 조회/수정 가능.
- PC/모바일에서 의류 등록 → 다른 기기에서 조회 가능.
- 대표 이미지 + 추가 이미지(최대 5장 제안), 이름, 카테고리, 브랜드, 색상, 계절 저장.
- 검색, 카테고리/브랜드/색상/계절/즐겨찾기 필터, 정렬 및 페이지네이션 정상 작동.
- 2개 이상 의류 선택 → 코디 저장 → 수정 → 재조회 정상 작동.
- 빈 상태/로딩/오류/업로드 실패/로그아웃 UI 존재.
- 최소 2개의 테스트 계정으로 다른 사람의 데이터에 접근할 수 없음을 검증.

### P1 완료 조건
- 착용 달력에서 원하는 날짜에 코디 또는 개별 아이템을 등록할 수 있음.
- 저장 코디 변경 전의 착용 기록도 보존.
- 단품별 착용 횟수/마지막 착용일/구매가 대비 착용당 비용 계산.
- 링크 추출 실패 시 수동 입력으로 복귀. 외부 사이트 내용은 명시적 확인 후만 저장.
- 본인 데이터의 CSV/JSON 내보내기 제공, 이미지 내보내기는 별도 ZIP 프로세스로 제공.

## 2. 기능 모듈
### F01. 인증 및 설정 (P0)
- 이메일/비밀번호 회원가입과 로그인; 개발 중 가입 허용 정책을 제한할 수 있도록 구성.
- 사용자별 테마(white/beige/brown), 기본 통화 KRW, 표시 이름.
- 모바일 세션 유지, 로그아웃, 이메일 확인/비밀번호 재설정.
- 향후 Apple/Google 로그인 추가 가능. 소셜 로그인은 P0 범위에서 제외.
- 추후 정식 공개 시 계정 삭제, 개인정보처리방침, 이용약관 구현.

### F02. 내 옷장 (P0)
- 의류 카드 필드: 대표 사진, 브랜드, 제품명, 대분류/소분류, 색상, 즐겨찾기.
- 상세 필드: 사이즈, 계절 복수, 소재, 태그, 구매일, 구매 가격, 구매처 링크, 메모.
- 수동 등록: PC 파일 업로드, 모바일 앨범/카메라(권한 요청), 여러 장 등록.
- 이미지 변환: HEIC 등은 플랫폼별 지원 형식 JPEG/WebP로 변환 후 업로드. 업로드 오류 재시도.
- 이미지 최대 5장(제품 정책), 장당 5MB 제한(서버 제한), 업로드 전 압축 권장.
- 아우터/상의/하의/원피스·셋업/신발/가방/액세서리, 하위 분류 포함.
- 필터: 대분류/세부 분류/브랜드/색상/계절/즐겨찾기/상태.
- 정렬: 최근 등록/이름/브랜드/구매 가격/최근 착용 (후자는 P1).
- 일반 삭제는 soft delete, 판매/기부/보관 상태를 별도로 제공.
- 이미 코디에 쓰인 옷을 비활성화하면 코디에 상태 경고를 표시.

### F03. 코디 만들기 (P0)
- 사용자가 아우터/상의/하의/신발을 골라 4슬롯 코디 생성.
- 원피스, 가방, 액세서리 지원. 여러 레이어가 필요한 경우 slot + position으로 확장.
- 코디 미리보기는 실제 옷장 이미지. 없는 슬롯에는 '선택 안 함' 표시.
- 코디 이름, 계절(복수), 상황(캐주얼/출근/격식 등), 태그, 메모, 즐겨찾기.
- 저장 전 유효성 검사: 최소 1개의 아이템, 타 회원 아이템/삭제 아이템 참조 금지.
- 코디 편집 중 미저장 변경사항 경고.

### F04. 저장한 코디 (P0)
- 4칸(2x2) 조합 썸네일을 가진 카드. 이름·계절·태그를 함께 표시.
- 계절/즐겨찾기 필터, 이름 검색, 최근 추가·수정 순 정렬.
- 수정, 복제, 삭제, 즐겨찾기. 카드 열면 구성품 상세/착용 기록(추후).

### F05. 착용 기록 (P1)
- 달력의 하루를 선택한 후 저장된 코디를 선택하거나 아이템을 직접 선택.
- 하루에 여러 코디/기록 등록 허용; 동일 기록 내 같은 옷 중복 등록 금지.
- 저장 시 wear_events + wear_event_items에 별도 스냅샷 링크 저장.
- 기록을 삭제하면 통계에 즉시 반영; 코디 자체 삭제/수정은 과거 기록에 영향 없음.
- 똑같은 코디를 다른 날 다시 입으면 별도 착용 이벤트.

### F06. 대시보드 및 옷장 통계 (P1)
- 내 옷 전체 개수, 활성/보관 개수, 최근 등록, 브랜드 분포, 카테고리별 비중.
- 최근 30/90일 착용 횟수, 총 구매가(정보가 입력된 옷만), 최근 미착용 아이템.
- '한 번도 안 입음'은 착용 데이터 입력 이후를 기준으로 안내, 과거 사실을 단정하지 않음.
- 착용당 비용 = 구매 가격 / 누적 착용 횟수, 착용 0회면 금액 대신 '기록 없음' 표기.
- 데이터 부재 시 분석 대신 기록 안내 표시.

### F07. 링크로 제품 등록 (P1)
1. 사용자가 HTTPS 상품 URL을 입력.
2. 서버가 도메인/리다이렉트/사설 IP/응답크기/시간 제한을 검증.
3. 이용이 허용되는 사이트에서 OG, JSON-LD 등 메타데이터 추출을 시도.
4. 원천 데이터에서 상품명/브랜드/대표 이미지 후보/가격 후보 추출, 신뢰도 낮으면 미입력.
5. '검토 후 등록' 화면에서 사용자가 수정/승인.
6. 실패 시 URL을 유지한 채 수동 입력 화면 표시.
- 무단 크롤링이나 접근제한 우회/저작물 재배포는 구현하지 않음.
- 자동 사진 다운로드/타인 공개는 저작권·이용조건 확인 전에는 비활성화.
- AI가 필요한 추론/분류는 추후 서버 측에서만 호출하고 API 키를 앱에 넣지 않음.

### F08. 백업/복원 (P1)
- 인증된 사용자의 JSON/CSV 내보내기. 민감한 개인 메모도 포함됨을 사용자에게 안내.
- 이미지 포함 ZIP 백업은 별도 동작으로 구현(파일 개수, 크기 제한, 실패 재시도).
- 복원 시 중복 처리/파일 매칭/스키마 버전을 검증.
- 최초 MVP에는 안전한 내보내기부터 제공하고 복원은 P1 후반에 추가 가능.

### F09. 공개/운영 기능 (P2)
- 운영자가 초대 코드/가입 허용 범위를 설정할 수 있도록 구성.
- 이메일 확인/비밀번호 재설정, 회원 탈퇴와 데이터 삭제, 보안 로그.
- 개인정보처리방침/이용약관/문의/오류 신고.
- 공개 코디 기능은 옵트인만 허용. 개인 메모/구매가/구매처 등 비공개 필드는 노출하지 않음.
- 동의 없는 상품 상세/타 사용자 옷장 노출 금지. 신고/삭제 기능 마련.

## 3. 화면별 상세 IA
### PC 상단 내비게이션
- 내 옷장 / 저장한 코디 / 코디 만들기 / 착용 기록 / 통계 / 더보기(설정·메모·공지)
- 레퍼런스의 공지·메모·추천 탭은 초기에는 '더보기' 또는 미노출. 실제 가치를 만드는 핵심 흐름을 우선.
- 모바일은 하단 5개: 옷장 / 코디 / 기록 / 통계 / 더보기. 저장한 코디는 코디 하위 탭.

### S01. 내 옷장 `/wardrobe`
- 상단: MY PERSONAL WARDROBE, 내 옷장, 짧은 안내 문구, '+ 옷 추가'.
- 1차 행: 대분류·세부 분류 드롭다운.
- 2차 행: 검색, 색상 필터, 즐겨찾기, 정렬, 필터 초기화.
- 그리드 카드: 정사각 또는 4:5 사진/중립 배경 + 하트 + 브랜드/제품명/카테고리·색상.
- PC(≥1440px): 5열, 중간 화면: 3~4열, 태블릿: 3열, 모바일: 2열.
- 카드 클릭 시 상세 화면; 클릭 영역과 하트 클릭 영역 분리.
- 147개와 같은 많은 데이터도 무한 스크롤 또는 페이지네이션.

### S02. 의류 상세 `/wardrobe/[itemId]`
- PC 좌측 큰 이미지/썸네일, 우측 브랜드·제품명·등록 필드·구매 정보.
- 모바일 상단 이미지 캐러셀 → 기본 정보 → 구매 정보 → 코디에서 사용한 목록.
- 수정·즐겨찾기·보관·삭제 메뉴. 삭제 전에 코디와 착용 기록에 대한 안내.

### S03. 의류 등록 `/wardrobe/new`
- 등록 방식 2가지: 직접 입력(P0), 링크 붙여 넣기(P1).
- 필수: 이름, 대분류(또는 세부 분류). 사진이 없으면 기본 플레이스홀더.
- 선택: 브랜드/색상/사이즈/소재/계절/태그/구매가/구매일/링크/메모.
- 웹은 단계형 폼 또는 오른쪽 미리보기, 모바일은 전면 폼.

### S04. 코디 만들기 `/outfits/new`
- PC: 좌측 옷 검색·필터 패널(35%), 우측 코디 보드(65%).
- 모바일: 상단 코디 보드 → 하단 카테고리 칩·옷 그리드, 또는 바텀시트.
- 옷 선택 시 슬롯에 즉시 반영. 각 슬롯의 교체/제거 가능.
- 코디 저장 후 상세로 이동, 사용자가 작성한 이름과 메모 보존.

### S05. 저장한 코디 `/outfits`
- PC 카드 3열, 태블릿 2열, 모바일 1~2열(가독성 기반).
- 코디 카드 = 아우터·상의·하의·신발 2x2, 없는 칸은 상태 표시.
- 상단 필터: 검색, 계절, 태그, 즐겨찾기, 정렬.
- 코디 이름 인라인 편집은 PC에서만 옵션, 모바일은 상세 편집 모달.

### S06. 착용 달력 `/calendar` (P1)
- 월 달력과 날짜별 기록 표시. PC에서는 우측 기록 리스트, 모바일은 달력 아래 리스트.
- '+ 오늘 입은 옷', '저장 코디에서 선택', '의류 직접 선택'.
- 과거 날짜로 등록 가능, 중복 착용 이벤트 구분.

### S07. 통계 `/insights` (P1)
- 통계 숫자 카드 + 카테고리 분포 + 가장 많이 입은 옷 + 안 입은 옷.
- 구매가를 입력하지 않은 옷은 가격 관련 분모에서 제외함을 명시.
- 계산 기간을 30일/90일/전체로 전환.

### S08. 설정 `/settings`
- 테마 세 가지, 사용자 프로필, 기본 통화, 내보내기(P1), 회원 탈퇴(P2), 공지 및 버전.

## 4. 디자인 토큰 제안
- 기본 배경: `#FFFFFF`; 대체 카드 배경: `#F6F7F9`; 보더: `#E6E8EC`.
- 주 포인트: `#3155D9`; 타이틀: `#20232D`; 설명: `#858997`.
- 추가 테마: 베이지/브라운은 해당 스크린샷의 원형 선택 UI를 참고해 구체 색상 조정.
- 권장 시스템 폰트: 한국어 Pretendard가 장착돼 있으면 사용하고, 없는 환경은 적절한 시스템 폰트 대체. 폰트 라이선스 확인.
- border-radius: 카드 12px, 입력 10px, 버튼 10px.
- 최소 터치 목표 44~48px, 모든 주요 입력에 label/오류 메시지.
- 사진 비율을 맞추되 상품 사진의 신축/찌그러짐 금지(`contain`).
- 모바일 최소 지원 너비 320px, 작은 화면 2열의 텍스트 줄수 조절.
- 기본 라이트 모드 우선. 다크 모드는 초기 범위 밖.

## 5. 데이터베이스와 관계
전체 실행용 초안: `CLOSET_schema_v1.sql`
- `auth.users` 1:1 `profiles`.
- `categories` 1:N `wardrobe_items` (계층형 분류).
- `wardrobe_items` 1:N `item_images`.
- `outfits` 1:N `outfit_items` N:1 `wardrobe_items`.
- `wear_events` 1:N `wear_event_items` N:1 `wardrobe_items`.
- `outfits` 1:N `wear_events` (선택적으로 원본 코디 참조).
- `import_jobs`는 향후 링크 자동 등록 상태 저장.
- 모든 개인 소유 테이블에 `user_id` 포함. 복합 외래키 `(id,user_id)`로 타인의 옷·코디를 참조할 수 없도록 함.
- DB RLS를 통한 격리 필수. 클라이언트 필터만으로 보안을 대체하지 않음.
- 사진은 private bucket에 `{user_id}/items/{item_id}/...` 경로로 저장. 인증 조회 또는 기간 제한 URL 사용.

### 데이터 관련 정책
- 카테고리는 전역으로 읽기 허용; 개인 코디/가격/메모는 전역 공개 불가.
- 아이템 소프트 삭제를 통해 기록 관계 보존. 실제 영구 삭제는 참조 관계 정리 후 수행.
- 회원 탈퇴 시 저장소 이미지 삭제 후 인증 계정 삭제/DB CASCADE 순서로 처리.
- 서버 관리자 키는 Edge Function 등 서버에만 보관. 클라이언트 코드/환경 변수에 노출 금지.

## 6. API/서비스 계층 설계
- `authService`: signUp/signIn/signOut/resetPassword/getSession.
- `wardrobeRepository`: list/get/create/update/archive/softDelete/toggleFavorite.
- `imageService`: compress, upload, get private image, delete (권한 검증 필수).
- `outfitRepository`: list/get/create/update/delete/duplicate.
- `wearRepository`: createWearEventFromOutfit/createWearEventFromItems/listByDate/deleteWearEvent.
- `insightService`: counts, mostWorn, leastWorn, costPerWear, filters.
- `importService`: submitUrl/getStatus/confirmDraft (P1). 웹 페이지/상품 정보 자동 추출은 서버에서만 실행.
- 모든 mutation은 Supabase 세션을 통해 실행. 여러 테이블을 함께 갱신하는 작업(코디 저장/착용 기록)은 RPC 트랜잭션으로 원자성 보장.
- TanStack Query 키: `['wardrobe', userId, filters]`, `['outfits', userId, filters]`, `['wear', userId, month]`.
- 로그인/로그아웃 시 캐시 격리·초기화. 양쪽 기기 변경 후 refetch 또는 Realtime 구독으로 최신화.

## 7. 출시·안전·법무 체크
- P0 단계에도 RLS, 사용자 간 정보 유출 테스트, 환경 변수 관리, 이미지 권한 필수.
- 공개 전: 계정 삭제, 동의/약관/개인정보처리방침, 백업, 오류 모니터링, 신고/고객 문의 창구 검토.
- 상품명/브랜드명은 사용자 기록으로 저장 가능하지만, 제3자 사진/로고의 무단 재배포는 피하고 외부 사이트 접근 조건 확인.
- 공개용 코디 공유는 private bucket 사진을 그대로 공개하지 않고, 사용 권리 확인과 별도 공유 자산 정책을 마련.
- 사용자 증가 시 이미지 요금/전송량, 데이터베이스 비용, AI API 요금 예산 상한 설정.

## 8. 개발 체크리스트 및 수락 테스트
- [ ] 로그인하지 않으면 나의 옷장에 접근 불가.
- [ ] 두 회원 A/B를 만들었을 때 A가 B의 의류를 읽고 수정하는 쿼리 실패.
- [ ] B의 item_id로 A의 outfit_items/ wear_event_items INSERT가 FK/RLS로 실패.
- [ ] B의 사진 경로를 A가 Storage API로 읽을 수 없음.
- [ ] 웹에서 사진 등록 후 모바일에서 조회할 수 있음.
- [ ] 모바일에서 즐겨찾기 변경 후 웹에 반영됨.
- [ ] 제품 사진이 없는 경우 플레이스홀더 제공.
- [ ] 옷 150~300개 등록 후 검색, 정렬, 페이지 로딩 문제 없음.
- [ ] 코디 저장 시 슬롯이 충돌하면 명확히 오류 처리.
- [ ] 코디 수정 후 이전 날짜의 착용 기록 구성은 변하지 않음.
- [ ] 착용 0회의 cost per wear에 0으로 나누기 오류 없음.
- [ ] 상품 URL이 유효하지 않으면 수동 등록 가능.
- [ ] 좁은 모바일 화면(320/360/390px)에서 좌우 스크롤/버튼 겹침 없음.
- [ ] 사진 업로드 실패 시 입력값을 유지하고 재시도 가능.
- [ ] 프로필 삭제와 사진 정리 시나리오 문서화 및 테스트.
