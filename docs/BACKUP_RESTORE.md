# 회원 데이터 백업·복원

2026-11-02. 설정 → 백업·복원에서 사용한다.

## 파일과 범위

- **전체 ZIP**: `data.json`과 의류 원본 사진, 브랜드 로고, 저장된 코디 PNG. 각 파일의 private 버킷/경로·MIME·크기·SHA-256을 manifest에 기록한다. 서버에서 한 시점의 회원 자료를 읽고, 사진 다운로드 후 같은 스냅샷인지 다시 확인한다. 누락/실패/동시 변경이면 완료 파일을 만들지 않는다.
- **JSON**: 사진을 제외한 데이터 복원용. 사진 메타데이터와 렌더 자산을 제거하고 로고·표현 설정의 파일 참조를 null로 만든다.
- **CSV ZIP**: 표별 CSV와 프로필 CSV를 UTF-8 BOM으로 제공한다. 금액은 원화이며 쉼표/따옴표/개행을 이스케이프하고 수식으로 해석될 수 있는 값은 텍스트로 만든다. CSV는 열람용이며 가져오기 형식은 아니다.

개인 의류(휴지통 포함), 코디/슬롯, 착용 기록/당시 아이템, 사용자 분류/이름·순서·숨김/삭제 이력, 브랜드, 색상 조합 즐겨찾기, 프로필·화면 설정을 다룬다. 기본 공유 분류는 앱 스키마를 사용하며 계정 인증정보·세션·비밀 키·전역 회원 목록·외부 링크 가져오기 작업 큐는 백업하지 않는다. 미완료 업로드/렌더는 완료 사진으로 취급하지 않는다.

백업은 암호화하지 않은 개인 자료이다. 전체/입력 ZIP 100MiB, JSON 16MiB, 사진 하나 5MiB, 사진 500개, 표별 10,000행/합계 25,000행으로 제한한다. 초과 자료의 대용량 스트리밍 백업은 후속이다.

## 복원 규칙

원래 계정으로만 복원한다. 파일 선택 시 JSON 버전/소유자/표/이미지 경로·바이트·해시를 검사하고 서버 dry-run으로 전체 참조·제약·권한·충돌을 검증한다. 예상 추가/유지 수를 확인한 후 사용자가 **확인하고 복원**을 눌러야 실제 저장한다.

동일한 기본 키와 내용은 건너뛴다. 기존 내용이 다르거나 서로 다른 ID가 같은 고유 이름/슬롯을 차지하면 HTTP 409로 전체 데이터 트랜잭션을 중단한다. 기존 기록을 덮어쓰거나 삭제하지 않으며, 현재 휴지통에 있는 옷을 옛 백업으로 강제 복원하지 않는다. JSON 복원은 기존 로고/렌더 파일 참조를 비교 대상에서 제외해 현재 사진을 유지한다.

프로필·화면 설정 복원은 기본 해제이며 별도 선택한다. 선택 시 미리보기에서 읽은 프로필 버전과 저장 시 버전을 비교한다. 이름·테마·정렬·카드 밀도만 변경하고 계정/인증/원화 정책은 변경하지 않는다.

데이터 저장은 단일 DB 트랜잭션이다. Storage는 별도이므로 사진 전송까지 원자적이라고 표시하지 않는다. 중단/응답 유실이면 같은 파일을 다시 선택해 이어서 복원한다. 원본 ID·경로를 재사용하므로 완료 자료가 중복 생성되지 않는다. 파일을 덮어쓰지 않고 기존 바이트와 해시가 다르면 중단한다.

## 보안과 구조

- `src/features/backup`: 버전 있는 파일 모델/ZIP·CSV/해시, 토큰을 고정한 서비스, 웹·네이티브 파일 입출력, 설정 UI를 분리한다.
- 내보내기는 RLS를 적용하는 invoker RPC이며 현재 `auth.uid()`만 읽는다. 복원/파일 완료의 공개 RPC도 invoker로 두고, 권한이 필요한 처리는 HTTP로 노출하지 않는 `app_private` definer 함수로 분리한다. 테이블/열 allow-list·행 소유자·기존 ID·연결 FK·DB 제약을 서버에서 재검증한다. 모든 함수에 빈 search_path, 명시적인 실행 권한을 설정한다. 익명 호출과 직접 복원 메타데이터 쓰기는 차단한다.
- 복원 허가 `backup_file_restores`는 회원별 RLS와 직접 쓰기 차단을 적용한다. 복원 트랜잭션에서 확인한 누락 파일만 15분간 업로드를 허가하고, 전송 후 크기/MIME/요청 해시를 확인해 닫는다. 일반 사진의 완료 경로 재사용 금지와 기존 Storage update/overwrite 금지는 유지한다.
- 작업 시작 시 세션 소유자를 확인하고 그 토큰을 고정한다. 계정 변경/화면 이탈 시 작업을 중단한다. 다른 계정으로 요청이 이어지지 않으며 5분 작업 제한과 수동 중단을 제공한다.
- ZIP 엔트리 수/경로/중복/확장자/압축 전 크기를 풀기 전에 확인한다. 파일을 임의 로컬 경로로 추출하지 않는다.
- 네이티브는 `expo-document-picker` 캐시 복사본으로 읽고 `expo-sharing`으로 저장한다. 사용한 임시 복사본만 정리한다. 네이티브 앱은 새 모듈을 포함해 다시 빌드해야 한다.

## 검증

- 단위 테스트: 한글 JSON, 다른 소유자/버전/미지 표·키 차단, PNG ZIP 원본 바이트, 손상/누락/경로 이동/압축 폭탄 크기 차단, CSV 수식/따옴표/개행.
- 실제 로컬 Supabase: 임시 두 계정의 전체 그래프/사진·로고·렌더 백업, 원본 제거 후 dry-run 무변경/실제 복원, 재시도 중복 방지, 사진 전송 실패 후 재개, 기존 파일 덮어쓰기/완료 경로 일반 재사용 차단, 익명/타 회원/직접 허가 쓰기 차단, 충돌 시 전체 롤백, FK 오류, 중복 ID, 프로필 버전 충돌.
- CLI 생성 migration의 새 기능만 남기고 동일한 기존 함수/extension diff 잡음을 제거했다. 새 스키마를 만드는 트랜잭션 검증과 명시적 ACL을 확인했다. 기존 migration은 수정하지 않는다.
- 타입 검사/ESLint/단위 197개, 실제 DB 회귀 156개(Node 13 + Vitest 143), Android/iOS JS export를 통과했다. 권한 경계 분리 후 백업 DB 7개를 다시 확인했다. 로컬 DB lint/security advisor 오류 없음.
- 브라우저에서 임시 계정의 ZIP/JSON/CSV 실제 다운로드, ZIP 재선택·미리보기·복원 완료, CSV 복원 차단을 확인했다. 1280/390/320px에서 가로 넘침을 확인했고 캡처는 제외된 `test-results/backup-desktop.png`, `backup-mobile.png`에 보관한다.
- 공용 DB에 `20261101234023_member_backup_restore.sql`과 `20261101234645_backup_private_boundaries.sql`을 적용했다. 새 기능으로 기존 회원 자료를 수정하는 DML은 실행하지 않았다. 공개 API 세 함수가 invoker이고 익명 실행이 차단된 것을 공용 DB에서도 조회했다.

실제 Android/iOS 파일 선택·공유 시트는 JS export와 구분하며 실기기 후속 확인 대상이다. 사용자의 실사용 자료로 복원을 자동 실행하지 않는다.
