# 회원별 카테고리 관리 — 2026-10-29

사용자가 확인한 범위: 코디와 연결된 기본 7종류는 유지하며 이름·순서·사용 여부를 수정하고, 각 종류 아래 세부 분류를 추가한다. 원본 첨부 문서의 전역 고정 분류 설계보다 이 요청을 우선한다.

## 사용

- **설정 → 카테고리 관리**에서 연다. 현재 경로는 `/settings/categories`이며 이전 `/categories`는 이 경로로 이동한다. 이후 설정 메뉴 통합은 `SETTINGS_UI_VALIDATION.md`를 참조한다.
- 현재 화면은 사용자가 선택한 A안(왼쪽 종류/오른쪽 세부 분류)이다. 이름은 연필을 눌러 편집 후 저장하고 사용 여부 스위치는 바로 저장한다. 취소하면 최신 조회 값으로 돌아간다. `CATEGORIES_A_VALIDATION.md` 참조.
- 순서 변경을 누르면 옷 종류는 위·아래 화살표, 세부 분류는 드래그 손잡이로 순서를 바로 저장한다. 수정 중인 행은 먼저 저장하거나 취소한다.
- 새 세부 분류는 옷 종류와 이름을 입력해 추가한다. 같은 종류 아래 이름 중복을 거부한다.
- 사용 안 함은 새 옷 등록에서 숨긴다. 기존 옷/코디/착용 기록은 유지하고, 기존 옷 편집의 원래 분류도 유지한다. 목록/코디 필터는 숨긴 분류의 기존 옷을 계속 찾을 수 있다.
- 기본 7종류 추가/삭제, 부모 이동, 영구 삭제는 이번 범위에 포함하지 않는다. 숨긴 항목은 다시 사용으로 저장할 수 있다.

## 구조와 보안

15번째 migration `20261029020000_member_categories.sql`을 기존 데이터를 초기화하지 않고 적용했다. 추가 환경 변수/패키지/외부 서비스는 없다. 원격 Supabase에는 적용하지 않았다. 다른 PC의 로컬 DB는 최신 코드를 받은 뒤 `npm run db:migrate`가 필요하다.

기존 category slug/부모와 코디 슬롯 관계는 그대로 유지한다. 전역 템플릿의 회원별 이름/순서/숨김을 별도 `category_preferences`에 두고 새 세부 분류만 본인 `categories.user_id` 행으로 만든다. 읽기 RLS는 전역 또는 본인 행만 허용한다. 인증된 회원도 테이블 직접 쓰기는 거부하고, 고정 search_path의 인증된 RPC로만 수정한다. 의류 trigger는 service-role 호출에서도 타인 분류 연결을 거부한다. 계정 삭제 시 해당 회원의 새 분류/환경설정만 cascade한다.

이름 수정은 updated_at CAS, 정렬은 기존 전체 형제 순서 비교를 사용한다. 회원 잠금으로 중복 이름·동시 저장을 직렬화한다. 생성 UUID/동일 결과 재시도는 응답 유실 뒤 중복과 오래된 입력 덮어쓰기를 막는다. Query key는 회원별이며 읽기 RPC도 명시한 owner와 auth.uid()를 대조한다. 쓰기는 시작 토큰에 고정하고 계정/화면 전환 시 요청 중단·늦은 결과 폐기를 수행한다.

## 검증

- TypeScript/ESLint와 단위 테스트 98개 통과. 이름·UUID·정렬 경계·숨긴 부모/자식·기존 분류 유지·코디 표시 이름과 canonical ID·개인 캐시를 검증했다.
- 실제 로컬 DB 통합 109개 통과(Node 13 + Vitest 96). 카테고리 8개 통합 시나리오는 두 회원/anon/직접 쓰기 금지/타인 연결 차단/중복·잘못된 부모/순서 충돌/동시 수정/응답 유실/토큰 고정/취소/1,005개 목록/계정 cascade를 확인했다. 숨긴 사용자 분류 의류의 검색·수정·코디 저장과 통계 이름 반영도 확인했다.
- SQL lint, 웹·Android·iOS export 통과. 공개 산출물 웹 32개/네이티브 3개에서 로컬 서버 키 미포함을 확인했다. 개발 서버 `/categories`와 JavaScript는 HTTP 200이며 실제 제공 번들에 새 기능이 포함된 것을 확인했다.
- 기존 사용자 계정 1개/의류 1개/DB 사진 1개/Storage 객체 1개를 유지했다. 테스트가 만든 개인 분류/설정은 모두 정리했다. 테스트는 생성한 fixture만 정리한다.
- 실제 브라우저 조작/외관·기기 제스처·접근성·웹↔기기 갱신은 기존 보류 상태를 유지했다. native export는 실기기 실행 검사와 구분한다.
