# 코디 편집 화면: 균형 분할형

2026-10-29. 사용자가 비교 목업의 균형 분할형을 선택하여 새 코디와 기존 코디 편집에 적용했다.

## 배치

- PC(1024px 이상)는 왼쪽 보드 54 : 오른쪽 선택 패널 46 비율이다. 두 영역은 20px 간격을 뺀 가용 너비를 flex로 나눠 사용한다.
- 이름과 주 저장 동작을 상단 한 줄로 모았다. 계절/상황/태그/메모/즐겨찾기는 보드 아래 접을 수 있다.
- 4개 기본 슬롯은 2×2이며 사진 전체를 contain으로 표시한다. 카드 크기에 맞춰 사진 높이를 140–170px로 제한했다. 반복되는 선택/교체 버튼 대신 사진을 누르고, ×로 제거한다.
- 레이아웃 측정값이 반올림되어 카드를 다음 줄로 밀던 문제를 막기 위해 카드 너비를 내림한다. 후보 카드도 같은 방식으로 2/3열을 유지한다.
- 오른쪽 종류 탭은 현재 슬롯을 전환한다. 서버에서는 이전과 동일하게 해당 종류의 본인 보유 의류만 조회·선택할 수 있다. 세부 분류/브랜드는 즉시 보이고 나머지 기존 필터는 접을 수 있다. 많은 후보는 PC 목록 안에서 스크롤하며 20개 서버 페이지를 유지한다.
- 구성 확인/선택 재조회/복제/최신 불러오기/삭제는 보드 아래 코디 도구에 모았다.
- 작은 화면은 보드를 표시하고 사진을 누르면 기존 전체 화면 선택 모달을 연다. 가방/액세서리 추가 슬롯을 제공하고 원피스·셋업은 기존 구성에 있을 때만 유지·제거할 수 있게 표시한다.

## 보존한 계약

DB migration, 환경값, 외부 서비스, Query/RPC/저장소 계약은 변경하지 않았다. 저장 전 검증, 최소 1개 구성, 회원 경계, 요청 잠금, updated_at 충돌 처리, 입력 보존과 미저장 이탈 확인을 유지한다. 일반 사용자 데이터는 검증에 사용하거나 변경하지 않았다.

## 검증

- TypeScript / ESLint / 단위 119개 통과.
- Android·iOS JS export 통과. 실기기 실행 검증과 구분한다.
- 공용 Supabase의 별도 임시 계정으로 웹에서 의류 8개와 사진을 준비했다. PC에서 상의/아우터/하의 선택, 코디 생성, 계절/상황/태그/메모 저장, 모바일 하의 교체와 변경 저장, 이탈 확인 취소, 코디 도구의 삭제와 목록 복귀를 확인했다.
- 1280px: 작업 영역 1184px, 좌측 629px / 우측 535px, 같은 y 좌표, 20px 간격. 1024px에서도 두 패널의 가로 넘침 없이 배치됨을 확인했다.
- 390px: 페이지/viewport 모두 390px, 158px 슬롯 카드가 두 열/두 행이다. 모바일 선택 모달의 후보와 실제 교체를 확인했다. 320px에서도 페이지가 가로로 넘치지 않는다.
- 브라우저 오류 로그 0개. 임시 계정의 코디·의류·사진만 검증 후 정리했다.

확인 스크린샷은 제외된 `test-results/editor-balanced/`에 보관한다. 실제 배포 버전은 Sites 결과를 기준으로 확인한다.
