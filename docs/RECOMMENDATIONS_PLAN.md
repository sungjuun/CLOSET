# 보유 의류 기반 추천과 이미지 표현

추천 UI의 최신 상태: `RECOMMENDATION_UI_VALIDATION.md`의 좌측 조건/우측 카드 및 모바일 필터 구조를 사용한다. 상황·최근 착용 제외를 기존 엔진/기록에 연결했고 이미지는 900×900 정사각형 플랫레이로 갱신했다. 아래 초기 구현의 900×1100 크기 및 마네킹 표현 설명은 과거 기록이다.

최신 변경(2026-10-30): 후속 요청으로 마네킹 UI·체형 선택·샘플 생성기를 제거했다. 현행 표현은 실제 제품 사진을 하나의 배경 위에 배치하는 플랫레이만 제공한다. 단색 배경 정리/미리보기/PNG 저장과 기존 설정 호환성은 `FLATLAY_VALIDATION.md`를 참조한다. 아래 두 표현 방식 및 VTO 계획은 최초 구현 당시의 기록이며 현재 활성 기능을 의미하지 않는다.

2026-10-30. 현재 코드 분석 후 다음 순서로 구현한다.

## 기존 경계와 호환성

- `/recommendations`는 준비 화면이다. 실제 저장은 `save_outfit` RPC와 `outfit_items`가 이미 소유권·상태·분류·중복·버전을 검사한다. 새 추천도 이 경계를 재사용하며 과거 코디와 원피스·셋업 자료는 변경하지 않는다.
- 사진은 `wardrobe-private`의 원본과 단기 signed URL을 사용한다. 추천 이미지용 private 저장소를 분리하며 원본 파일을 수정하지 않는다.
- 계절/소재/태그/대표 색은 기존 의류 필드다. 보조 색 HEX 배열만 선택적 컬럼으로 추가하고 기본값은 빈 배열이다. 스타일은 기존 태그를 읽는다. 피부색이나 퍼스널 컬러를 추정하지 않는다.

## 구현 단계

1. 추천 후보 읽기: 본인 active·미삭제 의류만 6종 루트로 분류한다. 계절을 적용하고 각 슬롯 최대 32개를 seed에 따라 순환 조회한다. 고정 ID는 후보에 포함하며 외부 회원/판매/삭제/다른 슬롯 고정은 거절한다.
2. 순수 추천 엔진: 색상 48%, 계절 18%, 스타일 14%, 소재 12%, 새로움 8%의 설명 가능한 규칙이다. 대표·보조 색, 색상각·명도·채도·색의 웜/쿨 성향을 사용하며 모르는 값은 중립값과 정보 부족 표시를 사용한다. beam search와 중복 제외·유사도 재정렬로 3–5개를 고른다. 실제 가능한 조합이 부족하면 부족 사유와 실제 개수만 표시한다.
3. 나열형: 원본 사진을 contain으로 배치하고 실제 ID·슬롯을 유지한다. 교체/고정/재추천, 코디 저장 시 PNG 자동 생성·private 저장과 다운로드를 연결한다.
4. 마네킹형: 슬림/보통/체격 3개 남성 샘플 템플릿이다. 샘플 표기를 화면과 저장 이미지에 넣는다. 실제 제품의 착용 결과라고 표현하지 않는다. renderer 인터페이스를 분리하고 실패 시 실제 아이템 나열형으로 돌아간다. 외부 AI API는 등록·호출하지 않는다.
5. 표현 저장: 기존 코디와 1:1인 표현 설정 및 생성 파일 예약/완료 테이블을 추가한다. 회원/코디 복합 FK, 버전 검사, RLS, private Storage 정책으로 분리한다. 기존 편집기에 표현 패널을 붙이며 코디 변경 뒤 이전 이미지를 현재 이미지로 재사용하지 않는다.
6. 검증: 순수 점수/고정/다양성/부족/실패 fallback, 실제 DB의 소유권·경합·파일 권한, 웹 PC/모바일 UI, native JS export와 타입·린트를 확인한다. 테스트 계정과 파일만 정리한다.

## 후속 작업

실제 Virtual Try-On은 별도 서버 adapter, 공급자 계약·과금·이미지 전송 동의·민감 자료 처리·작업 취소·보관 기간·품질 평가를 갖춘 후 연결한다. 현재 adapter의 기본 구현은 샘플이며 유료 또는 외부 AI 요청을 수행하지 않는다.

## 구현한 모듈과 사용법

- `engine.ts`: 순수 추천/점수/중복/고정. 기존 색상 도구와 분리된 실제 의류 추천이다. 후보 풀은 슬롯당 32개, 엔진 탐색은 슬롯당 16개/beam 96개로 제한한다. 전체 옷장의 전수 최적해나 취향의 객관적 점수를 보장하지 않는다. 최근 조합 제외는 현재 화면 세션의 최근 80개를 대상으로 한다.
- `service.ts`: 본인 후보·검증·기존 save_outfit 호출, 표현 설정 및 PNG 예약/완료. `outfit_items`에 실제 garment UUID를 기록한다. 의류 원본/코디 저장 RPC를 변경하지 않았다.
- `renderModel.ts`, `renderer.web.ts`, `renderer.ts`, `artwork.ts`: 공통 adapter와 플랫폼 구현. 웹은 원본을 다운스케일해 contain 배치한 독립 PNG(900×1100), 네이티브는 이미지 로드 후 View 캡처와 공유 시트를 사용한다. 원본 사진은 재작성하지 않는다. 마네킹 오류 시 실제 사진 나열형을 생성하며 취소는 재시도하지 않는다.
- `Screen.tsx`, `RecommendationCard.tsx`: 추천받기 → 고정/교체 → 표현 선택 → 코디 저장. 저장 버튼이 코디와 PNG 생성을 함께 실행한다. 단순 추천 조회는 DB에 코디를 자동 생성하지 않는다. 가능한 실제 조합 수가 적으면 3개 미만도 정직하게 표시한다. 사진이 없으면 이름·빈 영역을 표시한다.
- `SavedPresentationPanel.tsx`: 저장한 코디의 기존 보기·수정에서 표현/체형 복원과 이미지 생성. 편집 중이면 코디 변경을 먼저 저장한다. 기존 원피스 자료는 그대로 유지하며 새 6슬롯 표현만 제한한다.
- `outfit_presentations`, `outfit_render_assets`, `outfit-renders-private`: 회원/코디/버전/출처/체형/경로를 분리해 저장한다. 코디 저장은 성공하고 이미지가 실패한 경우 같은 코디 UUID로 재시도한다. 같은 렌더 UUID에는 같은 바이트만 허용한다. 수정 전 이미지는 과거 스냅샷으로 남고 현재 이미지로 표시되지 않는다.

## 검증 기록

- `npm run check`: strict 타입 검사, 경고 없는 린트, 단위 179개 통과(신규 추천/렌더/보조 색 13개 포함).
- 기존 `npm run db:test`: Node 13개 + Vitest 131개 통과. 이후 시작 토큰 고정 테스트를 1개 추가하고 신규 추천 통합 8개를 다시 통과했다. 검증한 서로 다른 DB 테스트는 총 145개이며 원본 사진/코디/착용/회원 분리 회귀를 포함한다.
- 새 통합 테스트는 실제 로컬 Supabase에서 후보 제한·고정·타 회원/익명 접근·의류 ID 저장·private PNG·덮어쓰기/임의 경로 거부·모드와 버전 경합·의류 상태/분류 변경·응답 유실·바이트 불일치를 확인한다. 테스트는 별도 계정/파일만 생성·제거한다.
- PC 1280px와 모바일 웹 390/320px: 3–4개 추천, 중복 교체 차단, 실제 옷 교체, 고정 후 재추천, 원본 사진 비율, PNG 다운로드 및 코디와 이미지 저장을 확인했다. 좁은 화면 문서 너비는 viewport와 같고 카드가 한 열로 배치된다.
- 세 체형 샘플 생성, 체격형 저장 후 기존 편집기 복원, 슬림형으로 변경·저장 후 새로고침 복원을 확인했다. PNG 출처와 원본 의류 ID는 DB에서도 대조했다. 브라우저 오류 로그 없음(기존 Auth SDK lock 옵션 폐기 예정 경고는 별도).
- iOS/Android JS/Hermes export 성공. Windows에서 iOS 네이티브 실행·실기기 화면 캡처/사진 공유 시트는 확인하지 못했다. JS export를 실기기 검증으로 대신하지 않는다.
- 22번째 migration은 reset 없이 공용 프로젝트에도 적용했다. 적용 전후 기존 회원 1/의류 19/코디 1/파일 41로 동일했다. 로컬 DB advisor는 경고 없음. 공용 advisor는 의도된 인증 사용자용 SECURITY DEFINER RPC(새 3개 포함)와 기존 leaked password protection 비활성 경고를 반환한다. 새 RPC는 직접 테이블 쓰기를 닫은 대신 소유권/버전 검증을 제공하는 경계이며 익명 실행은 금지한다. 기존 Auth 설정은 변경하지 않았다.
- 배포용 production 웹 빌드를 공용 DB에 연결한 별도 임시 계정으로 4개 추천·나열형 저장·체격형 마네킹 저장·PNG 다운로드까지 확인했다. 1개 코디에 실제 6개 의류 UUID, ready PNG 2개, mannequin/broad 설정을 대조했고 브라우저 오류 로그는 없었다. 검증용 사진은 합성한 테스트 도형이며 실제 회원 제품으로 위장하지 않는다. 임시 계정/파일은 검증 후 정확한 소유자 경로로 정리한다.

## 남은 범위

실제 VTO 제공자 연결/유료 호출, 실제 제품 착용 정확도, 남성 체형의 실측 피팅, 실기기 캡처·공유 및 보조기술 확인은 후속이다. 오래된 생성 이미지·실패한 pending 파일 자동 수거와 보관 기간 정책도 후속으로 두었다. 현재는 회원의 private 경로와 DB 경로를 보존하며 계정 삭제 시 파일을 먼저 정리한다. 원본 의류 수정 후 재생성하지 않은 이미지는 저장 당시 스냅샷이다.
