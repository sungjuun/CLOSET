# 코디 추천 UI — 조건 패널과 추천 카드

2026-10-30. 두 참고 이미지 중 실제 사진 플랫레이를 쓰는 두 번째 구성을 기준으로 구현했다. 이전 요청으로 제거한 마네킹·체형 선택, 헤더의 옛 테마 스위치/공지/메모 메뉴를 다시 추가하지 않는다.

## 화면과 동작

- PC: 제목/다른 추천 받기, 왼쪽 248px 조건 패널, 오른쪽 결과 영역. 결과 너비에 따라 3/2열로 조정하고 카드 폭을 정수 픽셀로 계산해 줄 밀림을 방지한다.
- 모바일/태블릿: 상황·스타일·계절 요약 칩과 필터 버튼. 필터는 스크롤 가능한 하단 패널로 열고 적용하면 닫는다. 좁은 화면에서는 한 열 카드와 '다른 추천 코디' 제목을 사용한다.
- 조건: 상황 7종, 스타일(전체/미니멀/캐주얼/포멀/스트릿/빈티지/클래식/스포티), 계절 4종 재선택 해제, 최근 30일 착용 제외. 기존 개수 3–5/아우터 포함은 추가 조건에 유지했다. 최근 착용 제외의 기본은 꺼짐이다.
- 조건 입력과 적용한 조건을 분리했다. 새 조건을 선택해도 기존 카드/이름을 즉시 버리지 않고, 적용 전이라는 설명을 표시한다. 적용/재추천 후 점수·이유·저장 메타데이터는 같은 조건을 사용한다. 초기화는 다음 적용 조건을 기본값으로 되돌린다.
- 카드: 추천 번호와 종합 점수, 정사각형 실제 사진 플랫레이, 이름·실제 아이템 개수 기반 설명·태그, 사용 아이템 사진, 저장/아이템 교체/더보기. 썸네일로 슬롯 교체가 가능하고 더보기에서 이름·색상 점수·상세 이유·고정·PNG 저장을 제공한다. 저장 후 기존 보기·수정 경로를 사용한다.
- 미리보기와 저장 이미지 모두 공통 `flatlaySize`/좌표의 900×900 PNG다. 옷을 자르거나 늘이지 않으며 기존의 단색 배경 처리/원본 보존/비공개 저장 경계는 유지한다.

## 데이터와 추천

- 상황은 기존 의류 태그의 명시적 일치를 스타일 평가 일부에 반영한다. 연관 태그가 없으면 중립값이며 이유에서 미입력임을 안내한다. 포멀/빈티지 별칭을 추가했다. 선택한 상황은 기존 `outfits.occasion`, 스타일·상황은 기존 코디 태그에 저장한다.
- `recentlyWorn(today)`는 시작 세션 토큰으로 본인 `wear_event_items`와 본인 `wear_events`를 읽는다. 달력 날짜의 오늘/29일 전을 포함한 30일만 조회하며 삭제/미래 기록은 제외한다. 복합 순서로 200행씩 모든 페이지를 읽고 실제 UUID를 중복 제거한다. 다른 회원의 기록은 RLS와 owner 조건으로 차단한다.
- 제외 옵션이 켜진 경우만 착용 기록을 읽고 엔진 후보에서 해당 UUID를 제거한다. 고정과 충돌하면 오류를 내고 수동 교체도 같은 제외 목록을 확인한다. 기존 슬롯별 후보 32개/탐색 16개/beam 96 제한은 유지하며 전체 옷장 전수 최적해를 보장하지 않는다. 조합 부족 시 실제 개수 또는 조건 조정 안내만 표시한다.
- 새 테이블·migration·비밀 키·API·환경 변수는 없다. 기존 저장 RPC, private 이미지, 회원 캐시 및 요청 취소를 그대로 사용한다. 외부 AI 요청은 수행하지 않는다.

## 검증

- strict 타입 검사, 경고 없는 lint, 단위 테스트 187개 통과. 상황 태그 평가/최근 착용 제외·고정 충돌/달력 월·연·윤년 경계/입력과 적용 조건 비교/설명 및 기존 저장 필드 5개 테스트를 추가했다.
- 실제 로컬 Supabase 추천 통합 9개 통과. 신규 테스트는 200행을 넘는 착용 기록에서 페이지 누락/중복, 본인/타인, 오늘/30일 시작 경계/이전/미래/삭제 기록을 검증했다. 기존 의류 ID/소유권/이미지 권한/버전/응답 유실 테스트도 유지한다.
- 임시 계정으로 PC 1280/1440px와 모바일 390/320px를 확인했다. 한 열/3열, 필터 패널 열기·닫기·적용, 조건 변경 중 기존 카드 유지, 카드 더보기/이름 수정/코디 저장/PNG 다운로드를 확인했다. 320px의 문서 너비는 320px, 카드 너비는 288px로 가로 넘침이 없다.
- 실제 등록 사진 5장은 원본을 읽어 임시 계정의 별도 파일로만 복사했다. 원래 계정/파일은 수정하지 않았다. 임시 의류 1개를 오늘 착용 처리한 뒤 옵션 적용 전 3개 카드 유지, 적용 후 해당 의류를 제외한 2개 조합 표시를 확인했다.
- 모바일 썸네일에서 다른 실제 아우터로 교체하고, 이를 고정한 재추천 2개 모두 같은 아이템을 유지하는 것을 확인했다. 부족한 신발/가방 등을 임의 생성하지 않는다.
- 저장된 코디/이미지와 items/regular 설정, 900×900 다운로드 PNG를 확인했다. 상황·스타일은 기존 필드로 저장하며 브라우저 오류 로그 없음. Android/iOS JS export 성공은 실기기의 캡처·공유·접근성 검증을 대신하지 않는다.

검증용 계정·착용 기록·복사 사진·생성 PNG는 정확한 fixture 소유자 경로에서만 정리한다. 기존 사용자 자료는 유지한다.
