# 12단계: 기간별 통계와 누적 착용당 비용

검증일: 2026-10-28 (Asia/Seoul). I01의 `/insights` 화면, 읽기 RPC, 저장소와 회원별 Query를 구현하고 코드·실제 로컬 DB·번들로 검증했다. 사용자 요청에 따라 브라우저·실기기 검증은 보류를 유지하며 Q01 전체 완료로 표시하지 않는다.

## 구현과 집계 기준

- 기본은 마운트 당시 지역 날짜/최근 30일이다. 30일·90일·전체 선택, 기준일 입력/오늘/새로고침을 제공한다. 기간은 양끝 포함이며 최소 날짜는 1900-01-01이다. 기준일 이후와 삭제된 기록은 제외하고 같은 날 별도 이벤트는 각각 센다.
- 현재 옷장 수·상태별 수·선택 기간 기록/미기록·누적 미기록 의류, 착용 이벤트/기록일/의류 착용 수, 통화별 구매가 합계, 대분류 분포와 브랜드 상위 10개/나머지를 표시한다. 로딩/오류를 실제 0으로 표시하지 않는다.
- 의류 수·분포·가격은 현재 등록된 휴지통 밖 의류 기준이다. 과거 기준일의 재고를 복원하는 기능은 아니다. 과거 기록의 이벤트/의류 착용 수는 나중에 휴지통으로 옮긴 의류의 스냅샷도 포함하므로 현재 의류 수와 구분한다.
- 착용당 비용은 현재 구매가를 기준일까지의 누적 기록 수로 나눈다. 선택 기간 내 횟수와 누적 횟수를 따로 표시한다. 가격 미입력 또는 누적 0회는 비용 null, 0원과 누적 1회 이상은 비용 0이다. 통화는 합치거나 환산하지 않는다.
- 의류 목록은 많이 기록/기간 내 미기록/최근 등록/전체 모드, 이름·브랜드 리터럴 검색, 서버 20개 페이지, 사진과 현재 상태·마지막 기록일을 제공한다. 실제 0건과 오류/로딩을 구분한다.

`20261028090000_insights.sql`을 기존 로컬 DB에 적용하고 실제 타입을 재생성했다. migration은 총 12개다. `insight_item_stats`와 `wardrobe_insights`는 security invoker/RLS/본인 owner를 유지하고 PUBLIC/anon 실행을 거부한다. 요약은 페이지 제한 없는 의류 관계를 PostgreSQL 안에서 집계해 API의 1,000행 반환 제한에 잘리지 않는다. 카테고리는 하위 분류를 대분류로 합산한다.

통계 요청은 시작 토큰과 AbortSignal을 사용한다. 캐시 key는 회원/기준일/기간/목록 조건을 포함하며 회원 교체 때 화면 상태도 초기화한다. 의류 생성·변경·삭제·복원과 착용 쓰기는 해당 회원의 통계 Query를 취소·무효화한다. 새 패키지/환경 변수/외부 서비스는 추가하지 않았다.

## 재현과 제한

```powershell
npm run db:migrate
npm run db:types
npm run check
npm run db:test
npx supabase db lint --local --level warning
npm run export:web
npm run export:native -- --output-dir dist/native
node scripts/check-public-bundle.mjs
```

기존 Node 24.22.1/npm 11.19.1 환경을 사용했다. 권장 Node 22.23.x/npm 10 검증과 구분하며 package.json/lockfile은 변경하지 않았다. 테스트는 loopback 및 직접 생성한 임시 두 계정/데이터만 사용했다. 종료 후 auth.users/wardrobe_items/outfits/wear_events/wear_event_items/item_images/storage.objects 모두 0건을 확인했다. 로컬 Supabase는 실행 상태로 유지한다. 원격 배포나 DB reset은 하지 않았다.

다음 개발은 L01 HTTPS 상품 URL 서버 검증/작업 상태다. O02–O03/H02/I01 화면과 Q01 기기간 갱신·접근성·실기기 확인, 원격 HTTPS/SMTP/배포는 남아 있다. 화면 검증의 재승인이나 브라우저 접근은 요청하지 않았다.
