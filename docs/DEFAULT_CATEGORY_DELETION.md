# 기본 세부 분류 삭제 및 확인 버튼 순서

2026-10-30. 재킷·코트·점퍼·패딩 등 기본 세부 분류에도 삭제 아이콘을 제공한다. 대분류와 코디 슬롯의 canonical ID는 유지한다.

## 동작

- 분류 삭제 팝업은 ‘세부 분류 삭제 확인 → 취소’, 옷 상세의 휴지통 안내는 ‘휴지통 이동 확인 → 변경 취소’ 순서다. 삭제 버튼이 위, 취소 버튼이 아래다. 로딩·오류·오래된 버전·중복 실행 방지는 유지한다.
- 분류를 삭제하면 본인의 활성/휴지통 의류를 같은 상위 종류로 원자적으로 이동한다. 의류 ID, 사진 메타데이터/파일, 코디 연결, 착용 스냅샷을 삭제하지 않는다.
- 사용자 분류는 기존처럼 물리 삭제한다. 공통 기본 분류는 공유 원본을 보존하고 회원별 삭제 기록으로 디렉터리에서 제외한다. 다른 회원은 같은 기본 분류를 계속 사용·편집·삭제할 수 있다. 삭제한 이름은 새 개인 분류로 다시 추가할 수 있다.

## DB

`20261030050302_member_default_category_deletion.sql`은 기존 삭제 기록을 보존하면서 기본키를 `(user_id,category_slug)`로 변경하고 네 함수를 갱신한다. 기존 RLS·실행 권한·빈 search_path를 유지한다. `member_categories`는 본인의 삭제 기록만 제외한다. 삭제 RPC는 인증, 소유권, 세부 분류 여부, 버전, 같은 상위 종류의 유효한 목적지, 트랜잭션 잠금을 검사한다.

삭제 결과는 재시도에 재사용한다. 삭제된 분류의 수정·순서 변경·합치기 목적지와 직접 의류 INSERT/UPDATE의 오래된 분류 재사용을 거절한다. 의류 분류 쓰기 트리거와 삭제 RPC가 동일한 회원별 잠금을 사용해 삭제와 신규 연결의 경합을 막는다. API 서명과 생성 타입의 필드는 바뀌지 않는다.

Supabase 스킬에 따라 로컬에서 DDL과 테스트를 검증하고 db pull로 migration을 생성했다. 무관한 pg_net extension 삭제 차이는 제외했다. 공용 프로젝트에 해당 migration 한 개만 적용했다. 추가 환경 변수·의존성은 없다.

## 검증

- 타입 검사·ESLint·단위 192개, 로컬 DB 전체 148개(Node 13 + Vitest 135) 통과.
- 카테고리 통합 17개에는 기본 분류의 회원별 삭제·활성/휴지통 의류 이동·사진 메타데이터/코디/착용 기록 보존·응답 유실 재시도·다른 회원 영향 없음·중복 이름 재생성·오래된 대상/정렬 거절 검증을 포함한다.
- 로컬 DB 보안 advisor 경고 없음. 공용 advisor의 기존 인증된 SECURITY DEFINER 쓰기 RPC 안내와 유출 비밀번호 보호 미사용 안내를 확인했다. 이번 변경은 새 RPC나 권한 확대가 없으며 삭제 RPC의 인증·소유자 검사를 통합 테스트했다.
- 웹에서 기본 분류 삭제 아이콘, 확인/취소 위아래 좌표, 취소 후 유지, 옷 상세의 휴지통 확인/취소 순서를 점검했다. 캡처는 Git에서 제외된 `test-results/category-delete-confirm.png`, `test-results/wardrobe-trash-confirm.png`다.
- Android/iOS JS export를 통과했다. 실기기 테스트는 포함하지 않는다. 공용 API는 임시 계정만 사용해 확인하고 정리한다. 실제 사용자의 분류·옷·코디는 변경하지 않는다.
