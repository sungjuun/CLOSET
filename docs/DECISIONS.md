| D08 | 원본 SQL 보존, 검증된 migration 별도 관리 | 로컬 실행 및 보안 통합 테스트 완료. 원격 적용은 별도 |
| D09 | 사진 최대 5장은 대표 포함 총 5장 | 0–4 고유 슬롯 예약과 Storage 정책으로 강제. 업로드 트랜잭션 동안 예약 잠금 |
| D10 | 로컬 테마는 기기 메모리 상태 | 사용자 프로필 저장/기기간 동기화는 인증 구현 후 |
| D11 | 모바일 세션은 SecureStore | 기기 암호화 저장, JS UI 상태와 토큰 분리 |
| D12 | 날짜는 사용자 지역 날짜, 통계는 착용 이벤트 수 | 동일 날짜 여러 이벤트 허용. 비용/0회는 null로 표시 |
| D13 | 최초에는 모바일 하단 5개 탐색 유지 | 사용자의 직접 UI 변경 요청으로 D43에서 대체 |
| D14 | 레퍼런스의 화면 계층과 카드 구성을 채택 | 개인 로고/백업/공지·추천·메모는 기능 추가 지시로 해석하지 않음 |
| D15 | 이미지의 픽셀 폭으로 CSS breakpoint를 확정하지 않음 | DPR/리사이즈 여부 불명. 현재 그리드 계약을 유지하고 W03에서 실제 화면으로 조정 |
| D16 | 신규 가입 차단과 이메일 공급자 활성화를 분리 | auth.enable_signup=false, auth.email.enable_signup=true. 공급자까지 끄면 기존 계정 로그인도 막힘 |
| D17 | Auth 링크는 PKCE와 고정 callback 경로 | 임의 next URL을 받지 않으며 요청한 기기/브라우저의 verifier로 교환 |
| D18 | 코디/착용 테이블의 클라이언트 쓰기는 아직 닫음 | 최소 구성/활성 의류/스냅샷을 강제하는 RPC 구현 전 직접 쓰기를 열지 않음 |
| D19 | 사진 파일을 삭제한 후 예약 행 삭제 | 파일이 남은 예약 삭제를 막아 최대 5장 제한 우회 방지. 객체 덮어쓰기/이동은 닫고 새 경로 사용 |
| D20 | 등록 폼마다 안전한 UUID 하나를 유지 | expo-crypto 사용. 동일 ID/내용 재시도는 기존 행 반환, 다른 내용은 충돌 처리. 응답 유실 후 중복 삽입/무단 덮어쓰기 방지 |
| D21 | 기본 목록은 20개, created_at/id 역순 | 같은 시각에 등록된 행도 안정적으로 정렬. soft delete 제외, 상태별 필터는 W03에서 확장 |
| D22 | W01은 사진 없이 등록/조회 | 선택 필드 검증·오류 복구·소유권을 먼저 완성. 사진/검색·필터/편집은 각각 W02/W03/W04 |
| D23 | 가격 공란은 null, 입력한 0원은 0 | 천 단위 쉼표와 소수 둘째 자리 허용. 구매 날짜는 실제 달력 날짜 문자열로 저장해 timezone 변환 방지 |
| D24 | 사진은 pending 예약 → Storage → ready 완료 RPC | 파일 없는 행을 목록 사진으로 노출하지 않음. 재접속 시 완료/정리 제공, 자동 만료 정리는 후속 |
| D25 | ready 사진에 별도 is_primary 필드 | 사진 순서 재정렬 없이 대표 교체. unique partial index로 대표 중복 차단, 삭제 RPC가 다음 ready 사진 선택 |
| D26 | 사진은 기기에서 디코딩·최대 2048px WebP 변환 | 원본 30MiB/36MP 제한, 출력 5MiB. 웹 WebP 인코더 미지원은 흰 배경 JPEG fallback. 원본/EXIF를 그대로 업로드하지 않음 |
| D27 | signed URL TTL 60초, 캐시 stale 40초/조회 중 45초 갱신 | URL을 DB/로컬 저장소에 저장하지 않고 회원 전환 때 취소/삭제. 발급된 bearer URL의 즉시 폐기를 의미하지 않음 |
| D28 | 업로드 재시도는 같은 UUID와 변환 바이트 유지 | 응답 유실 시 저장된 파일과 바이트 비교 후 완료, 다른 파일 덮어쓰기 거부. ready 경로에는 파일 재삽입도 거부 |
| D29 | 사진 작업은 시작 회원의 토큰으로 끝까지 실행 | 새 회원 토큰을 중간에 읽지 않음. 모든 네트워크 요청에 취소 연결, 계정 교체/화면 이탈 후 결과 반영 차단 |
| D30 | W03 검색은 DB 읽기 RPC의 리터럴 부분 일치 | 이름/브랜드/색상, 대소문자 무시. 검색 문자열을 PostgREST 필터 문법/SQL로 조합하지 않아 %, _, 쉼표/따옴표도 문자로 검색 |
| D31 | 필터 AND, 대분류는 하위 포함, 선택지는 본인 전체 옷장 기준 | 필터 변경 시 페이지 초기화, 삭제로 페이지가 사라지면 재집계 후 보정. 선택지는 다른 필터와 독립적이며 null/공백 값은 제외 |
| D32 | 구매가 정렬은 통화별 그룹, 미입력은 마지막 | 환율 변환 없이 서로 다른 통화의 금액을 직접 비교하지 않음. 0원은 유효한 값 |
| D33 | 검색 조건은 메모리 상태, Query key에는 조건 전체 포함 | 계정 교체 때 새 화면/캐시로 전환. 새로고침 후 필터 복원/URL 공유는 이번 범위 밖 |
| D34 | W04 편집은 updated_at 조건부 갱신 | 다른 세션의 변경을 자동 덮어쓰지 않음. timestamp 문자열을 Date로 변환하지 않고 원래 정밀도로 전달 |
| D35 | 응답 유실 재시도는 현재의 원하는 값과 비교 | 같은 값이면 쓰기를 반복하지 않고 현재 행 반환. 즐겨찾기는 boolean 명시, 삭제는 이미 휴지통이면 성공, 복원은 기존 상태 보존 |
| D36 | 일반 삭제는 복원 가능한 휴지통 | 삭제 시 Storage/코디/착용 연결을 제거하지 않음. 영구 삭제/자동 만료/파일 수거는 별도 운영 단계 |
| D37 | 수정 폼 snapshot은 자동 재조회로 교체하지 않음 | 오류·충돌 때 초안 유지. 사용자 확인 후 최신 내용으로 다시 편집. 폼의 취소 버튼과 최신 정보 교체에만 입력 폐기 확인 |
| D38 | 변경 뒤 조회는 백그라운드로 갱신 | 오프라인 재조회가 편집 화면을 계속 잠그지 않음. 기존 조회 취소 후 캐시 무효화, 쓰기 요청에는 15초 abort 타이머 |
| D39 | O01은 7슬롯 메모리 초안, 슬롯당 1개/position=0 | 기본 4칸과 원피스/가방/액세서리 지원. 레이어/재정렬과 DB 저장은 다음 단계로 분리 |
| D40 | 선택과 구성 확인 때 현재 의류를 다시 읽음 | 후보에서 active/소유자/분류를 제한하고 선택 후 상태 변경도 주기/포커스/수동 조회로 감지. O02 저장 때 다시 원자적으로 검증해야 함 |
