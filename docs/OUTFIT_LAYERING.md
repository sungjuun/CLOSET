# 코디 겹쳐 입기 (2026-11-02)

- 아우터와 상의는 각각 최대 3벌, 순서는 안쪽에서 바깥쪽이다. 다른 종류는 기존 한 벌 선택을 유지한다.
- 보드의 ‘겹쳐 입기 추가’로 새 옷을 선택한다. 사진은 해당 레이어 교체, ×는 해당 옷만 제거, ↑/↓는 입는 순서를 변경한다. 이미 선택된 옷은 다른 레이어 후보에서 비활성화한다.
- 기존 draft.items의 문자열 ID는 position=0으로 호환된다. 추가 ID만 optional layers에 보관하고 DB에는 기존 outfit_items(slot,position,item_id)로 평탄화한다. 별도 테이블/개인 데이터 이전은 없다.
- 서버는 아우터·상의의 position 0..2, 다른 슬롯의 position=0, 빈틈 없는 순서, 중복 없는 실제 보유 의류를 검사한다. 회원 소유권·활성 상태·분류·원자적 저장·충돌 검사는 유지한다.
- 저장/재편집/복제와 과거 착용 기록 스냅샷이 모든 레이어 ID를 보존한다. 카탈로그에 같은 슬롯의 사진을 함께 보여준다.
- 기본 플랫레이는 기존 배치 그대로다. 레이어가 있는 코디의 미리보기/PNG에는 모든 옷을 비중첩 배치하며 원본 사진 비율을 유지한다. 웹은 동일 좌표의 SVG를 PNG로, 네이티브는 동일 미리보기를 캡처한다.
- 자동 추천 엔진의 선택 개수 규칙은 유지한다. 추천을 저장한 뒤 편집기에서 수동으로 겹쳐 입기를 추가할 수 있다.

## 검증

- 타입 검사와 ESLint, 단위 테스트 201개 통과.
- 로컬 Supabase 통합 테스트: Node 13개 및 Vitest 146개 검증 통과(전체 회귀 및 관련 파일 재검증).
- DB: 11개 실제 ID 저장/재조회/재정렬/복제/착용 기록, 원본 변경 후 스냅샷 보존, 중복·위치 누락·4번째 레이어·타인 의류·부적합 종류 거부. 렌더 저장 시 바깥 레이어도 상태 재검사.
- PC 브라우저: 재킷+코트, 셔츠+니트 선택·정렬·저장, 3벌 제한, 중복 후보 비활성화, 안쪽 제거 후 승격, 모든 의류가 포함된 PNG 저장 성공.
- 모바일 웹 390px: 레이어 추가 전체 화면, 추가/삭제/저장/새로고침 복원, 320px 가로 넘침 검사. 테스트용 그림과 임시 회원만 사용한다.
- Android/iOS JS 번들 export 통과. 이번 변경의 네이티브 실기기 검증은 수행하지 않았다.
